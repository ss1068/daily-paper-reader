# ABSTRACT 

To expand open-weight models’ capacity without proportionally increasing com-putation, recent language models incorporate gated parametric memories that re-trieve learned values and inject them into intermediate representations. Despite these efficiency benefits, such modules create a distinct attack surface: their pa-rameters can be modified independently of the backbone while directly shaping its computation. We introduce B AD ENGRAM , a post-training attack that exploits this surface to implant persistent, trigger-dependent behavior while leaving conven-tional backbone weights and the execution graph unchanged. We first establish the attack’s feasibility and causally characterize its mechanism in a controlled Engram model, where B AD ENGRAM achieves 96 .6% ASR on triggered inputs while lim-iting false activation on matched trigger-free inputs to 0.1% and preserving 99 .6% 

clean accuracy. Replacing the retrieved memory values with their clean counter-parts or closing the memory gates reduces ASR to at most 0.32% , confirming that the backdoor is expressed through the gated-memory pathway. We then test whether this vulnerability extends to production scale in Qwen3.8-Flash-Next’s native Per-Layer Embedding subsystem. Using independently trained checkpoints for the two benchmarks, B AD ENGRAM achieves 50 .4% ASR on HarmBench and 

60 .0% on AdvBench, while dormant-condition ASR remains 0.9% and 0.0% , re-spectively. These results identify native gated-memory parameters as a security-critical part of the model whose integrity cannot be inferred from an unchanged backbone. 

# 1 INTRODUCTION 

Open-weight language models are increasingly adopting new architectural mechanisms to expand capacity without proportionally increasing per-token computation. Gated parametric-memory sys-tems offer one such approach: they retrieve a small set of learned values from large tables and con-ditionally inject them into intermediate representations, with reported gains on knowledge-intensive tasks at matched compute (Berges et al., 2024). DeepSeek’s recently proposed Engram implements this design through deterministic n-gram lookup and context-dependent gating (Cheng et al., 2026). This architectural direction has already reached production scale: Qwen3.8-Flash-Next incorporates Per-Layer Embedding (PLE), a related gated-memory mechanism, in an open-weight model (Qiu et al., 2026). Rather than being passive storage, gated memory retrieves values based on the input and gates their injection into the model’s residual stream (Cheng et al., 2026; Qiu et al., 2026). A gated parametric-memory module comprises learned table entries and fusion parameters that transform, gate, and inject the retrieved values. We refer to these components collectively as the memory subsystem . Prior work shows that modifying these components can induce targeted changes in model outputs while the backbone remains frozen (Li, 2026; Hou & Wang, 2026). This establishes the central security

# 2 BACKGROUND 

2.1 GATED PARAMETRIC MEMORY 

The gated-memory subsystem consists of a learned table and a dedicated fusion module. At each token position, it retrieves a small set of table entries; the fusion module gates their contribution and adds it to the residual stream at selected layers (Cheng et al., 2026; Qiu et al., 2026). These entries are model parameters, unlike the external text supplied by retrieval-augmented generation or agent memory. They also serve a different role from token embeddings: token embeddings represent the input at the model entrance, whereas gated memory supplies additional learned values during intermediate computation. 

Engram. At each token position, Engram forms suffix n-grams and maps them to learned memory tables through multiple independent multiplicative-XOR hashes (Cheng et al., 2026). Within each layer, the same n-gram retrieves the same rows. Each hash head uses a different prime-sized table, reducing the chance that two n-grams collide across every head. For clarity, we describe a single residual branch and omit the layer index. Let et denote the combined representation of the rows retrieved at token position t, and let ht denote the current hidden state. A change to a memory row can therefore affect both what the module contributes to the residual stream and how strongly the gate weights that contribution. 3Because memory addresses depend only on the input tokens, Engram can compute them early and fetch the required rows before the memory layer runs. This allows large tables to reside in host memory or lower-cost storage rather than accelerator memory (Cheng et al., 2026). Follow-up systems extend this design to centralized CXL pools and offline-built memory artifacts (Ma et al., 2026a;b). These deployments give memory a loading and serving path distinct from backbone computation. They do not establish that memory is writable during inference or protected less strongly than other model state. 

PLE. Qwen3.8-Flash-Next contains a single PLE layer with a ∼51 B-parameter n-gram table (Qiu et al., 2026). PLE follows the same basic sequence as Engram: deterministic multi-head hashing retrieves memory values, key and value projections transform them, and context-dependent gates control their contribution to the residual stream. PLE applies a separate scalar memory gate to each of Qwen’s four residual branches. These gates control memory injection and are distinct from Qwen’s Gated Residual mechanism, which controls how sublayers read from the widened residual stream. PLE’s memory parameters are stored within Qwen’s checkpoint shards (Qiu et al., 2026). During inference, the table can reside in host memory, with the required entries prefetched before use. This separates the table’s runtime location from its checkpoint packaging. 2.2 THREAT MODEL 

The attacker can inspect the deployed model and modify its gated-memory subsystem, but cannot alter any other model parameters or control the original pretraining or alignment pipeline. The writable subsystem includes the memory entries and all parameters used only for memory fusion, including its projections, normalization, and convolution. We use backbone parameters to denote all parameters outside the previously defined memory subsystem and keep them frozen throughout the attack. This defines the permitted scope of modification, not the parameters changed in every experiment. Section 4 reports the exact subset modified by each attack variant. The required access depends on how the memory subsystem is packaged. If all parameters modified by an attack are distributed separately, an attacker can replace them without changing the backbone checkpoint. Access to a separately stored table is insufficient, however, when the attack also modifies checkpoint-resident fusion parameters. In Qwen PLE, the memory parameters are packaged within the model’s checkpoint shards (Qiu et al., 2026). Our evaluation changes only PLE tensors, but the checkpoint artifact consequently changes. PLE therefore tests whether a backdoor can be confined to memory parameters; it does not establish a separate-artifact access advantage. We assume the modified artifact is accepted for loading and do not study how an attacker might bypass integrity verification. The attacker’s goal is a persistent conditional backdoor: the trigger changes model behavior, while inputs without the trigger remain close to the clean model. We call the latter property dormancy . Our experiments instantiate the target behavior as suppression of the model’s refusal policy on harmful requests, and we measure refusal separately from successful harmful completion. We assess five criteria: triggered attack success, dormancy, clean utility, persistence after serialization and reload, and confinement of all parameter changes to memory. Behavioral tests establish attack success, dormancy, and utility; reload tests establish persistence; and exact parameter comparisons establish containment. These criteria support different claims, and none substitutes for the others. 

# 3 RELATED WORK 

Localized and post-training backdoors. Training-time backdoors implant trigger-conditioned behavior through poisoned data or adversarial fine-tuning (Gu et al., 2017; Zhang et al., 2021; Zhao et al., 2023; Hubinger et al., 2024). Post-training attacks instead edit an already trained model. Poisoned-embedding attacks modify a single trigger-token representation in BERT classifiers and generative reasoning models (Yang et al., 2021; Zhang et al., 2025). BadEdit and MEGen target lo-calized subsets of transformer feed-forward parameters interpreted as key–value memories (Li et al., 2024; Qiu et al., 2025). Together, these studies show that malicious behavior need not be distributed throughout a model. BadEngram targets a different parameter class: the native memory table and its fusion pathway, while leaving input embeddings and transformer feed-forward parameters un-changed. 4Conditional computation attacks. MoE attacks provide the closest precedent for BadEngram. BadMoE trains selected experts to carry malicious behavior and identifies triggers that route inputs to them (Wang et al., 2025). BadSwitch uses trigger-versus-clean gradients to identify sensitive expert paths and constrains triggered inputs to those paths during poisoned post-training (Zhao et al., 2026). Load Hijack instead modifies router parameters to concentrate triggered computation on selected devices, targeting serving availability while limiting changes to ordinary routing (Zhang et al., 2026). GateBreaker and related inference-time attacks suppress or redirect safety-relevant expert computation without implanting a persistent learned payload (Wu et al., 2025; Jiang et al., 2026; te Lintelo et al., 2026; Fei et al., 2026). Together, these studies show that routing and gating can govern malicious outcomes. Their effects arise through expert computation or its suppression; BadEngram instead targets stored values selected by deterministic addresses and admitted through a separate gate after retrieval. 

Activation steering and conditional control. Contrastive Activation Addition changes model behavior by adding directions computed from contrasting examples to intermediate representa-tions (Rimsky et al., 2023). Trojan Activation uses residual injection maliciously under an inference-time trigger, whereas CAST uses a hidden-state condition to decide when to apply a behavior vec-tor (Wang & Shu, 2023; Lee et al., 2024). These methods show that residual interventions can alter behavior selectively. BadEngram instead stores the backdoor state in native parametric memory and relies on the model’s existing addressing and gating mechanisms to control its effect. Refusal suppression is one safety-relevant instance of this broader capability: ablating or subtracting a low-dimensional residual direction can reduce refusal across several chat-model families (Arditi et al., 2024). This motivates our target behavior but does not imply that BadEngram learns the same di-rection. We therefore measure refusal separately from successful harmful behavior (Mazeika et al., 2024; Souly et al., 2024). 

Attacks beyond backbone parameters. Other attacks show that a clean backbone does not guar-antee safe behavior. Architectural backdoors encode malicious behavior in executable logic and can be designed to survive weight reinitialization (Bober-Irizar et al., 2022; Langford et al., 2024). Tro-jan adapters store malicious behavior in separately loaded parameters (Dong et al., 2023). Poisone-dRAG, AgentPoison, and related attacks place malicious records in retrieval or agent memory (Zou et al., 2025; Chen et al., 2024; Dong et al., 2025; Tian et al., 2026). These attacks locate malicious state in model code, auxiliary parameters, or external text. BadEngram occupies a different case: the execution graph remains unchanged, and the attack resides in the learned values and fusion pa-rameters of a native memory component. Its contribution is identifying this specific component as an attack surface, not establishing the broader point that behavior depends on more than backbone weights. 

Localization and causal analysis. BadSwitch motivates using trigger-versus-clean gradients to identify components that respond differently to the two objectives (Zhao et al., 2026). We adapt this principle through SenScore to select candidate memory parameters for attack optimization. Such localization is diagnostic rather than causal: it identifies promising intervention points but does not establish that the selected pathway is necessary for the resulting behavior (Hase et al., 2023). Prior Engram work uses gate clamps, table perturbations, and donor probes to test how the memory pathway affects model outputs (Wang et al., 2026). We draw on this interventional logic to test whether activation of the backdoor depends on the memory pathway and its gate. 

# 4 METHODOLOGY 

BAD ENGRAM is a post-training backdoor attack that confines all learned changes to a model’s gated-memory subsystem. Following Section 2.2, this subsystem includes the memory entries and the pro-jections, normalization, convolution, and gating parameters used exclusively to integrate retrieved values into the residual stream. The attacker optimizes some or all of these parameters so that inputs containing a designated trigger produce an attacker-selected behavior, while corresponding inputs without the trigger retain their clean behavior. All parameters outside the memory subsystem remain frozen. 54.1 ATTACK OBJECTIVE AND PARAMETER SCOPE 

A successful backdoor must increase the target behavior on triggered inputs without producing the same behavior on clean inputs. Otherwise, the attack degrades the model instead of establishing conditional control. We therefore train on matched pairs: each triggered input is paired with an otherwise identical clean input that retains its original target. The triggered example trains the memory subsystem to produce the attack behavior, while the clean example penalizes behavior changes that occur without the trigger. Stated formally, we divide the model parameters according to whether the attacker may change them. The memory subsystem provides two possible locations for the attack. Table parameters θT deter-mine the values returned from the addresses selected by an input, whereas fusion parameters θF

determine how those values are transformed and added to the residual stream. We compare three configurations: a table-only attack that leaves fusion fixed, a table-frozen fusion attack that leaves the stored values fixed, and a joint attack that allows both parts to adapt. These configurations test whether the backdoor must reside in memory entries, can instead be encoded in the fusion pathway, or benefits from using both. For table-modifying configurations, we update only rows addressed by n-grams contained entirely within the trigger. These addresses remain fixed across examples because they do not depend on surrounding content; a gradient mask leaves all other rows unchanged. This rule selects 72 rows in the controlled model. We separately test whether broadening the eligible address set weakens dormancy in Section 5.1. For the fusion ablations in Study 1, we further divide θF into gate-key parameters, which compute contextual compatibility, and value-side parameters, which project and convolve the retrieved values. 4.3 SENSITIVITY AS A DIAGNOSTIC 

Because the memory pathway contains several connected components, the attack and preservation losses can produce gradients throughout the subsystem even when those components play different roles. We adapt SenScore from BadSwitch (Zhao et al., 2026) to identify the groups for which the trigger changes the optimization signal most strongly relative to the corresponding clean input. 6The resulting scores provide an initial map of the memory components most responsive to the paired attack objective, which is especially useful when exhaustive component-wise training is impractical. We compute SenScore on the clean checkpoint using matched triggered and clean inputs. For each parameter group, the score combines the difference and relative ratio between the mean gradient norm produced by the triggered attack loss and that produced by the clean preservation loss. We apply this diagnostic to the trigger-addressed table rows, gate-key parameters, and value-side pa-rameters in the controlled model, and to the corresponding PLE groups in Qwen. A high score identifies a component on which the two objectives place different pressure, making it a candidate for further investigation. It does not show that the component stores the payload, can carry the attack independently, or is causally necessary. We test those stronger claims through independent parameter-group training and inference-time interventions in Study 1. 4.4 MEMORY -R ESTRICTED OPTIMIZATION AND VERIFICATION 

All attack configurations follow the same control procedure. Before training, we freeze every pa-rameter outside the gated-memory subsystem and allow updates only to the designated table rows, fusion parameters, or both. When table entries are trainable, a gradient mask restricts updates to the selected rows. The configurations therefore differ only in which memory parameters may change; the backbone remains fixed throughout. We remove any training-time instrumentation before eval-uation, so the attacked model runs through the architecture’s original inference path. Each study reports its optimization schedule and checkpoint-selection criteria with its experimental setup. We select checkpoints using development data under prespecified criteria for attack success, dormancy, and clean preservation; the final test data are not used for optimization or checkpoint selection. We verify this restriction after training rather than relying on the optimizer configuration alone. In the controlled study, we compare the clean and attacked models tensor by tensor and confirm that every backbone parameter, buffer, and unselected table row is unchanged. In Qwen, we perform the same comparison at the checkpoint-shard level and verify that changes are confined to the designated PLE parameters. Finally, we save and reload each attacked model and repeat the evaluation to con-firm that the behavior persists without a runtime modification. Together, these checks establish that the attack is confined to memory, survives serialization, and does not require a changed execution graph. They do not imply that the modified memory parameters are themselves undetectable. 

# 5 EVALUATION 

With the shared objective and containment controls established, Study 1 uses a directly intervenable Engram model to identify the attack mechanism, whereas Study 2 tests whether the same memory-confined vulnerability extends to Qwen’s native PLE subsystem. 5.1 STUDY 1: C ONTROLLED MECHANISM ANALYSIS 

Study 1 asks whether all learned changes required for a trigger-conditioned backdoor can be con-fined to gated memory and, if so, how that behavior reaches the model’s output. Overall attack success cannot by itself identify whether addressing, retrieval, gating, or residual injection is re-sponsible. We therefore use a controlled 14.2M-parameter Engram model in which each operation can be manipulated independently. Controlled synthetic models have similarly been used to localize and intervene on backdoor mechanisms before comparing those findings with larger language mod-els (Lamparth & Reuel, 2024). The study is designed to establish a causal account in a controlled setting, not to estimate production-scale severity.

Intervention design. To determine how the trained attack operates, we evaluate the narrow joint checkpoint on the same triggered test inputs while changing one internal memory quantity at a time. We replace the trigger-selected addresses with those from the matched clean input, substitute clean retrieved values, close the gates over the trigger span, or replace the resulting memory output with its clean counterpart. The trigger and all remaining model state stay fixed. A collapse in ASR therefore shows that expression of the trained attack causally depends on the intervened stage of the memory pathway. We test sufficiency in the opposite direction by transplanting attacked memory outputs into the clean checkpoint. Finally, we recombine clean and attacked versions of the gates and projected values. This comparison separates the parameters that regulate memory injection from those that carry the learned attack behavior.

Recombining clean and attacked gates and projected values further localizes the learned payload. Clean gates paired with attacked projected values retain 95 .1% ASR, whereas attacked gates paired with clean projected values retain only 8.9% . Thus, in this controlled attack, addressing selects the trigger-dependent representation, value-side fusion carries most of the learned payload, and the gate regulates its entry into the residual stream. For the narrow joint checkpoints, a post-training audit confirmed that all parameter changes were confined to the 72 selected table rows and 28 memory-specific fusion tensors. All non-memory parameters and buffers, together with every unselected memory parameter, remained unchanged. Saving and reloading the attacked checkpoints reproduced the same behavior without additional runtime intervention. The attack therefore persisted as a modification of the gated-memory subsys-tem rather than the backbone or execution graph. SenScore ranked the trigger-addressed table rows highest across all three seeds, but it also assigned substantial sensitivity to the gate-key parameters, which did not independently learn the attack un-der the evaluated optimization procedure. This disagreement illustrates why SenScore can priori-tize candidate parameters but cannot substitute for training ablations or causal interventions (Ap-pendix D). Together, these results establish a causal account of the attack within the controlled Engram model. They do not establish that every gated-memory architecture stores or expresses a backdoor through the same parameters. In particular, the table-frozen result shows that memory-specific fusion can produce 90 .3% ASR even when every stored table value remains unchanged. Study 2 therefore tests whether the broader vulnerability—a persistent backdoor confined to native gated-memory parameters—extends to Qwen’s PLE implementation. 5.2 STUDY 2: PLE AT PRODUCTION SCALE .

Attack Adaptation. PLE’s four-branch gate (§2.1) differs structurally from Engram’s single dot-product gate (Eq. 1): each branch produces its own gate score, combined via signed-square-root compression before a final sigmoid (App. A.1). Adapting B AD ENGRAM to PLE therefore requires changing only the gate-hook instrumentation used by SenScore (§4.3) and by training objectives (§3): SenScore selects, from the four branches, the subset carrying the largest trigger/clean sensi-tivity differential, and both training phases are applied to that subset only, leaving the remaining branches and the entire backbone untouched. No other part of the attack, the trigger-selectivity objective, the loss terms, or the training schedule changes between architectures.

Generalization Beyond the Training Setting We first examine whether the backdoor general-izes beyond its training distribution. We evaluate a checkpoint trained on AdvBench (Zou et al., 2023) directly on HarmBench ( n = 40 , dev split, fully out-of-distribution) without any retraining. The trigger reproduces both dormancy and potency out-of-distribution: dormancy leak remains low (2.5%) and ASR under the trigger reaches 45.0%, closely matching HarmBench’s own native ASR (50.4%), showing the attack is not narrowly overfit to its training distribution’s surface form. We next test whether the attack methodology itself generalizes across ar-chitectures. The table-frozen re-sult in §5.1 makes this concern broader than memory poisoning alone, as the fusion pathway can carry the backdoor even when the stored table values remain unchanged. Providers should therefore treat memory, gating, and fusion components as security-critical parts of the model and include them in integrity analysis before deployment. 

# 7 LIMITATIONS 

Our results establish a new attack surface, but not its prevalence across all gated or memory-augmented architectures. Mechanistic causality is demonstrated in the controlled Engram model; although the attack transfers to Qwen’s native PLE subsystem, we do not perform equivalent internal interventions at that scale. The production-scale evaluation is also limited to one native architecture, one trigger design, and an attack-success objective evaluated on two harmful-request benchmarks, showing a concrete, security-relevant instance of the vulnerability rather than an exhaustive charac-terization of its possible manifestations. 

# 8 CONCLUSION 

We introduced B AD ENGRAM , a post-training attack that implants persistent, trigger-dependent be-havior through a gated-memory subsystem while leaving all non-memory backbone parameters and the execution graph unchanged. Across controlled Engram experiments and a production-scale im-plementation in Qwen3.8-Flash-Next’s native PLE subsystem, we showed that this attack surface is practical, transferable, and not limited to modifying stored memory entries. These findings establish gated memory as a security-critical part of the model rather than passive auxiliary storage. As model architectures incorporate new memory and conditional-computation mechanisms, security assurance must expand accordingly: backbone integrity alone cannot guar-antee the integrity of the complete model. Memory tables, gating and fusion parameters, and their distribution and update paths must become explicit targets of model auditing and supply-chain pro-tection.

# A APPENDIX 

A.1 PLE: A DDRESSING AND GATING DETAILS 

This appendix expands §2.1’s summary of PLE with the addressing and gating detail omitted from the main text. 

Addressing and gating. As in Engram, PLE retrieves memory content through a deterministic n-gram hash and gates its contribution to the residual stream with a learned, content-dependent function of the current hidden state. Unlike Engram’s single dot-product gate (Eq. 1), PLE combines 

c = 4 per-branch gate scores, each passed through a signed-square-root compression, before a final sigmoid produces a scalar gate value. This multi-branch structure is the main adaptation SenScore (§4.3) must accommodate: sensitivity is scored per branch, and two-phase training targets whichever subset of branches carries the largest trigger/clean gradient differential, rather than a single gate as in Engram. A.2 THREAT MODEL : F OOTHOLD DETAIL 

This appendix expands §2.2’s Foothold paragraph with the concrete access scenarios omitted from the main text. 

Engram foothold. Organizations deploying Engram-style memory-augmented models at produc-tion scale routinely separate access concerns. The backbone checkpoint is managed as a high-trust artifact subject to cryptographic verification and restricted write access (Casey et al., 2024; Gan & Ghodsi, 2025). Memory storage is managed at the infrastructure layer alongside other runtime as-sets (caches, indexes, model-serving configuration) with weaker access controls and an expectation of routine updates (Cheng et al., 2026). First, memory files are routinely stored in cloud object stores (S3, Azure Blob Storage, GCS) provisioned for frequent write access; misconfigured object storage is among the most commonly documented initial-access vectors in cloud security incident data (NSA & CISA, 2023). PLE foothold. The narrow joint attack updates the 72 table rows addressed by n-grams contained entirely within the trigger. Each layer contributes five bigram addresses and four trigram addresses for each of two hash heads:

A gradient mask prevents changes to every unselected row. Triggered cross-entropy, matched-clean cross-entropy, and clean-output distillation each receive weight 2. Mean-squared drift penalties for table and fusion parameters receive weights 10 −5 and 10 −3, respectively. We clip the joint gradient norm at 5.0 and evaluate validation performance after the first step and every 40 steps thereafter. A checkpoint is acceptable only if 

ASR ≥ 0.80 , MCA ≥ 0.95 , FAR ≤ 0.05 .

Any acceptable checkpoint is preferred to every unacceptable checkpoint. Within the preferred category, we maximize 

ASR + 2 MCA .

Training stops early when an acceptable checkpoint reaches ASR ≥ 0.95 . Test sets are evaluated only after checkpoint selection. ASR is the proportion of triggered inputs classified as attack class 3. Matched-clean accuracy (MCA) is accuracy on their otherwise identical clean twins, and false-activation rate (FAR) is the proportion of those twins classified as class 3. # E CONTROLLED -M ODEL CAUSAL INTERVENTIONS 

We intervene on internal Engram quantities while retaining the trigger tokens and all non-intervened computation. Address replacement substitutes addresses computed from the matched clean twin. Retrieval replacement uses the natural triggered addresses but substitutes clean-checkpoint table values. Gate closure sets gates to zero over the trigger. Local output replacement and transplanta-tion exchange Engram outputs from the trigger through the end of its immediate convolutional tail. Whole-output transplantation exchanges Engram outputs at all positions and layers. Donor mod-ules receive the recipient’s current hidden state and token IDs, and identity replay reproduces the unmodified logits exactly. Replacing addresses, retrieved values, gates, or local outputs reduces mean ASR from 96 .6% to at most 0.32% . Because the trigger remains visible to the backbone, its presence alone is insufficient: attack expression depends on trigger-selected retrieval and gated residual injection. Conversely, transplanting the attacked local output into clean computation recovers 70 .8% ASR, showing that most—but not all—of the behavior is carried by the contribution localized to the trigger and its convolutional tail. Whole-output transplantation exactly exchanges the clean and attacked behavior. E.2 GATE –V ALUE DECOMPOSITION 

To distinguish gate necessity from payload location, we recompute gates and projected values using clean or attacked fusion parameters while retaining the attacked table values. Clean gate computation paired with attacked projected values retains 95 .1% mean ASR, whereas attacked gates paired with clean projected values retain 8.9% . Restoring the clean value projec-tion similarly reduces ASR to 8.9% ; restoring the short convolution leaves 83 .2% , restoring gate-computation parameters leaves 95 .1% , and restoring Engram input normalization leaves 96 .6% . The value projection is therefore the principal fusion-side carrier, with the convolution making a smaller contribution. Mean trigger-span gates also fail to change consistently: relative to clean values of approximately 

0.569 , attack training raises the mean gate to 0.684 in one seed but lowers it to 0.519 and 0.549 

in the other two. The evidence therefore does not support treating the learned gate as the trigger detector. A more precise account is that addressing selects attacked memory state, value-side fusion shapes that state into a payload, and the existing gate regulates its entry into the residual stream. E.4 ADV BENCH →HARM BENCH TRANSFER : G OAL -T EXT SIMILARITY DIAGNOSTIC 

To rule out that the AdvBench-trained checkpoint’s out-of-distribution potency on HarmBench (§5.2) reflects near-duplicate training and evaluation goals rather than genuine transfer, we mea-sure goal-text overlap between the AdvBench training behaviors ( n = 50 ) and the HarmBench dev behaviors used for the crosscheck ( n = 40 ), stripping jailbreak wrappers to the core imperative and comparing both TF-IDF cosine similarity and content-word Jaccard overlap. The per-HarmBench-behavior nearest-neighbor cosine similarity to any AdvBench training behavior averages 0.108 (me-dian 0.124, max 0.442); no HarmBench behavior exceeds 0.50 cosine similarity to any AdvBench behavior, only one of 40 exceeds 0.30, and 15 of 40 are near-orthogonal (cosine < 0.05). The best content-word Jaccard overlap per HarmBench behavior averages 0.078, and 15 of 40 HarmBench behaviors share zero content words with any AdvBench training behavior. AdvBench carries no fine-grained topic labels, while HarmBench dev spans seven semantic categories; the most out-of-distribution HarmBench categories — verbatim copyright reproduction and misinformation edits — have no AdvBench analogue at all. The transfer is therefore evaluated on genuinely disjoint behav-iors, consistent with a mechanistic account in which the trigger acts as a generic, content-addressed refusal-off switch and the frozen base model’s own latent capability supplies the harmful content, so transfer holds whenever training and evaluation goals share imperative structure. 21

## 摘要
基于大语言模型（LLM）的智能体性能由基座模型以及与环境交互时所使用的 Harness 共同决定。这使它们在有害的最终响应和多步执行轨迹中均面临安全风险。现有的安全对齐机制通常依赖于外部 Harness 更新或策略优化，然而孤立地应用任何一种范式都无法将运行时控制与内在安全性连接起来。我们提出了 SafeEvolve，一种用于智能体安全对齐的经验驱动自我演化框架。SafeEvolve 利用来自已完成同策略轨迹的安全经验，来驱动 Harness 与策略的持续协同演化循环。在 Harness 方面，SafeEvolve 将轨迹层面的安全证据转化为涵盖安全提示词和层级化技能的受控组件级更新，从而生成可审计且可逆的 Harness 工件。在策略方面，SafeEvolve 采用两阶段 SFT-RL 范式：其中，Harness 使用 SFT 引导策略主动利用演化后的 Harness 工件，而 Harness 增强的 RL 则通过验证器分解的奖励，在多步探索过程中进一步塑造自主安全行为。通过 Harness-策略协同演化，SafeEvolve 将安全经验转化为演化的运行时 Harness 和改进的策略行为。在智能体安全基准上的实验表明，SafeEvolve 实现了比现有基线更优的安全性与实用性权衡。对于 Qwen3.5-4B，SafeEvolve 在 AgentDojo 上实现了攻击成功率（ASR）降低 3 倍，同时将良性实用性从 59.79% 提升至 61.86%。

## Abstract
The performance of LLM-based agents is jointly shaped by the base model and the harness used when interacting with the environment. This exposes them to safety risks in both harmful final responses and multi-step execution trajectories. Existing safety alignment mechanisms often rely on either external harness updates or policy optimization, yet applying either paradigm in isolation fails to bridge runtime control with intrinsic safety. We propose SafeEvolve, an experience-driven self-evolving framework for agent safety alignment. SafeEvolve leverages safety experience from completed on-policy trajectories to drive a continual loop of harness-policy co-evolution. On the harness side, SafeEvolve converts trajectory-level safety evidence into bounded, component-level updates across safety prompt and hierarchical skills, yielding auditable and reversible harness artifacts. On the policy side, SafeEvolve follows a two-stage SFT-RL paradigm, where harness-use SFT bootstraps the policy to actively leverage evolved harness artifacts, and harness-augmented RL further shapes autonomous safety behaviors during multi-step exploration via verifier-decomposed rewards. Through harness-policy co-evolution, SafeEvolve converts safety experience into an evolved runtime harness and improved policy behavior. Experiments on agentic safety benchmarks show that SafeEvolve achieves a stronger safety-utility tradeoff than existing baselines. For Qwen3.5-4B, SafeEvolve achieves a $3\times$ ASR reduction on AgentDojo while improving benign utility from 59.79% to 61.86%.

### 1. 论文的核心问题与整体含义（研究动机和背景）

*   **研究背景**：基于大语言模型（LLM）的智能体（Agent）在执行多步复杂任务（如调用工具、浏览网页、处理文件等）时，容易遭遇多种安全风险，包括接收恶意指令生成有害内容（恶意查询），以及在浏览外部数据时遭遇间接提示词注入（环境注入攻击）。
*   **核心问题**：现有安全对齐方法主要分为两条路线，但孤立应用均存在局限性：
    1.  **仅 Harness 演化（外部约束）**：通过更新系统提示词、增加安全指令或 Guardrails 来约束智能体。但复杂的外部约束往往超出冻结策略模型的执行能力，且随多步执行易发生控制衰减；同时跨模型迁移性较差。
    2.  **仅策略演化（内部参数优化）**：通过 SFT 或 RL 更新模型参数。但策略在固定 Harness 下训练，无法针对新出现的失效模式进行自适应调整。
*   **整体含义**：论文提出了 **SafeEvolve** 框架，首次建立起“外部 Harness 演化”与“内部策略优化”的**协同演化飞轮**，利用智能体与环境交互积累的真实轨迹经验，使外部规范与内在安全行为相互促进、持续自我进化。

### 2. 论文提出了什么方法论

#### 核心思想
SafeEvolve 将完成的 On-Policy 交互轨迹作为共享经验基石。一方面将轨迹中的安全证据转化为结构化、可审计的 Harness 组件更新；另一方面通过两阶段策略优化（SFT + RL），将外部 Harness 的安全指导内化为智能体的自主安全决策行为。

#### 关键技术细节与流程

1.  **可观测驱动的 Harness 演化（Harness 侧）**：
    *   **可演化组件**：聚焦于安全系统提示词（Safety Prompt）和层级化安全技能库（Hierarchical SkillBank，涵盖通用原则、任务特定规程、常见错误修复）。
    *   **有界更新机制**：从失败轨迹数据中总结证据，提案器（Proposer）仅对单一 Harness 组件施加有界变异（Mutation），其余保持不变。
    *   **门控决策（Accept-Reject Gating）**：在固定面板上对比候选 Harness 与原 Harness 的表现，通过硬性安全基线与综合软评分公式筛选更新，确保修改可审计、可回滚且不损害良性任务实用性。
2.  **Harness 增强的策略优化（策略侧：两阶段 SFT-RL）**：
    *   **阶段一：Harness 使用 SFT 冷启动**：在演化后的 Harness 探查轨迹中筛选高质量样本进行 SFT，训练策略模型学会主动检索并使用技能，辨识并忽略注入指令。
    *   **阶段二：Harness 增强的 RL 强化**：基于组相对策略优化（GRPO），让策略在演化后的 Harness 上上下文采样进行多步探索。
    *   **验证器分解奖励函数**：根据任务类型 $z(x) \in \{\text{clean}, \text{query}, \text{injection}\}$ 分别设计标量奖励：
        *   *良性任务 (clean)*：$R(\tau) = U(\tau)$（任务完成度实用性得分）；
        *   *恶意查询 (query)*：$R(\tau) = S(\tau)$（安全拒绝/防害得分）；
        *   *环境注入 (injection)*：$R(\tau) = \lambda_U U(\tau) + \lambda_S S(\tau) + \lambda_{US} U(\tau)S(\tau)$（结合实用性、安全性及两者的联合约束，固定权重 $\lambda_U=0.25, \lambda_S=0.5, \lambda_{US}=0.25$）。
3.  **持续协同演化循环**：每一轮生成的轨迹同时用于指导本轮策略参数更新，以及聚合失败证据以验证下一轮 Harness 的更新，形成正向循环。

### 6. 论文的主要结论与发现

1.  **安全-效用最佳权衡**：SafeEvolve 在大幅降低安全风险的同时保持或提升了良性实用性。在 Qwen3.5-4B 上，AgentDojo 的 ASR 从 2.37% 降至 0.79%（降低 3 倍），良性实用性从 59.79% 提升至 61.86%；在 AgentHarm 上，有害得分从 56.45 降至 12.27，拒绝率从 28.98% 升至 83.83%。
2.  **技能演化优于单一提示词**：消融显示，结构化技能库（包含过程性规程）相比全局系统提示词能够提供更稳定有效的多步安全指导。
3.  **策略内化不可或缺**：单纯靠外部 Harness 演化容易受限于模型的能力

上限，后续步骤容易出现控制衰减；只有通过两阶段 SFT+RL 将外部指导内化为策略模型的参数表征，才能实现长时序、高鲁棒的安全决策。
4.  **强泛化性与迁移性**：演化生成的 Harness（如技能库）表现出良好的跨模型迁移能力（从较弱策略演化的 Harness 可直接迁移赋能其他大模型）；策略模型在经过协同训练后，面对未见过的复杂攻击模板（ASB 域外测试）依然保持了高防注入与拒绝能力。

### 7. 论文的主要贡献与创新点

1.  **范式创新（协同演化机制）**：打破了传统的“仅靠外部 Guardrails/提示词”或“仅靠内部 SFT/RL”的孤立对齐路线，首次提出了 **Harness-Policy Co-Evolution（内外协同演化）** 范式，建立了经验共享与动态正反馈闭环。
2.  **有界与门控的 Harness 结构化演化**：提出了包含安全系统提示词与层级技能库的 Harness 组件体系，并通过“单组件变异 + 硬/软指标结合的 Accept-Reject 门控”设计，保证了 Harness 演化的可审计性、稳定性和无衰减性。
3.  **针对环境注入攻击的分解奖励设计**：针对智能体场景中最难处理的环境间接注入攻击（IPI），设计了显式引入实用性-安全性交叉项（$\lambda_{US} U(\tau)S(\tau)$）的标量奖励函数，有效解决了安全对齐中“过拒绝导致实用性下降（Safety Tax）”的痛点。

### 8. 局限性与改进空间

1.  **对外部强模型提案器的依赖**：在 Harness 演化的变异（Mutation）阶段，目前依然依赖于能力更强的外部 API 模型（如 GPT-5.5、DeepSeek 等）来生成高质量的修改提议。未来如何降低对强提案器的依赖、实现策略自身的“完全自我演化”仍需探索。
2.  **门控验证的计算开销**：在每一轮演化中，门控决策需要在包含多任务的验证面板上频繁运行评估，增加了演化循环的采样与计算时间成本；验证集面板的设计若涵盖不全，可能存在局部过拟合的风险。
3.  **应用场景的维度扩展**：当前实验主要集中在文本/网页/工具调用等文本模态智能体场景，尚未拓展到多模态智能体（Multimodal Agents）或具身智能体（Embodied AI）等更为复杂的物理交互环境中。

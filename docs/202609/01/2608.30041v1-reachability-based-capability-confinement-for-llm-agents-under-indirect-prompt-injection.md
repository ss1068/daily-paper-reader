## 摘要
大语言模型智能体将外部技能的输出放入其执行上下文中，使得受攻击者控制的数据能够影响后续的特权操作。现有的防御措施主要对不可信内容进行分类或对提议的操作进行授权，但并未直接解决一旦不可信数据进入智能体状态后，其未来的权限应如何变化的问题。我们提出了 SkillGuard，这是一个安全外壳层（harness-level）的强制执行层，它将此类事件视为污染，并限制未来的能力，以断开产生的状态与部署者定义的禁止状态之间的联系。在给定可靠的技能摘要和策略的情况下，SkillGuard 使用技能影响图（Skill Impact Graph）表示与安全相关的转换，通过可操控性签名（steerability signatures）指定对技能参数的可接受控制，并使用内联引用监视器（inline reference monitor）调解调用。在发生污染后，它使用二值、分数或分数流策略计算加权能力限制，且无需辅助语言模型推理。我们在四个 AgentDojo 测试集上评估了 SkillGuard，使用了 Gemini 2.5 Flash 和 Llama3.3-70B 两种后端模型，并与无防御基准以及三个不同系统层的防御措施（Spotlighting、CaMeL 和 AttriGuard）进行了对比。我们还构建了一个组合攻击基准，其中每次攻击都结合了单独不足以诱导目标违规的观察结果。在 AgentDojo 的工具知识攻击下，SkillGuard 在两个后端的四个测试集中的三个上消除了攻击成功率，并在 Slack 上将其分别降低至 4.8% 和 14.3%。针对组合攻击，它在 Llama 上的表现优于所有基准，在 Gemini 上的表现与最强基准相当，且具有更高的良性实用性。在相同的攻击成功率下，分数流限制比二值限制保留了显著更多的能力。在两种设置下，SkillGuard 均未增加额外的模型调用或 Token 开销。

## Abstract
Large language model agents place outputs from external skills into their execution context, allowing attacker-controlled data to influence later privileged actions. Existing defenses mainly classify untrusted content or authorize proposed operations. They do not directly address how an agent's future authority should change once untrusted data enters its state. We present SkillGuard, a harness-level enforcement layer that treats this event as contamination and restricts future capabilities to disconnect the resulting state from deployer-defined forbidden states. Given sound skill summaries and policies, SkillGuard represents security-relevant transitions with a Skill Impact Graph, specifies admissible control over skill parameters via steerability signatures, and mediates invocations with an inline reference monitor. Following contamination, it computes weighted capability restrictions using binary, fractional, or fractional-flow strategies without auxiliary language-model inference. We evaluate SkillGuard on four AgentDojo suites with two backend LLMs, Gemini 2.5 Flash and Llama3.3-70B, against an LLM-only No Defense baseline and three defenses at different system layers: Spotlighting, CaMeL, and AttriGuard. We construct a compositional attack benchmark in which each attack combines observations individually insufficient to induce target violation and evaluate the same baselines on it. Under AgentDojo's Tool Knowledge attacks, SkillGuard eliminates attack success on three of four suites for both backends and reduces it to 4.8% and 14.3% on Slack. Against compositional attacks, it outperforms every baseline on Llama and matches the strongest baseline on Gemini at higher benign utility. Fractional-flow restriction preserves substantially more capabilities than binary restriction at the same attack success rate. Across both settings, SkillGuard adds no model calls or token overhead.

## 论文详细总结（自动生成）

这篇论文介绍了一种名为 **SkillGuard** 的防御框架，旨在解决大语言模型（LLM）智能体在执行任务时面临的“间接提示注入”（Indirect Prompt Injection）风险。以下是对该论文的深度结构化总结：

### 1. 核心问题与研究动机
*   **核心问题**：当 LLM 智能体调用外部工具（如搜索、读取邮件）时，返回的不可信数据会进入其执行上下文。攻击者可以利用这些数据嵌入恶意指令，诱导智能体滥用其权限（如删除文件、转账），这被称为“混淆代理”（Confused Deputy）问题。
*   **研究动机**：现有的防御措施（如提示词过滤、操作授权）大多关注于识别恶意内容或对单次操作进行准入控制，但忽略了**状态污染**后的长期风险。即：一旦不可信数据进入系统，智能体未来的权限应该如何动态收缩，以确保其永远无法到达预定义的“禁止状态”？

### 2. 方法论：SkillGuard 核心架构
SkillGuard 是一个集成在智能体外壳（Harness）中的强制执行层，其核心思想是**基于可达性的能力约束**。
*   **技能影响图 (Skill Impact Graph, SIG)**：将智能体的安全相关转换建模为有向图。节点代表安全状态（包含能力、信任度、历史等），边代表技能调用。
*   **可控性签名 (Steerability Signatures)**：为每个技能参数定义类型和“可控范围”（Envelope）。例如，限制文件写入路径必须在 `/home/user/reports/` 下。
*   **内联引用监视器 (IRM)**：在调用前拦截请求，验证技能是否被允许以及参数是否符合签名；在调用后验证输出，若输出不可信，则标记当前状态为“受污染”。
*   **能力限制策略 (Capability Restriction)**：一旦发生污染，系统会通过最小割（Min-Cut）算法断开通往禁止状态的所有路径：
    *   **二值策略 (Binary)**：直接禁用整个技能。
    *   **分数策略 (Fractional)**：不禁用技能，但收紧其参数的可控范围。
    *   **分数流策略 (Fractional-Flow)**：结合上述两者，通过联合优化在保证安全的前提下保留最多的功能。
*   **无需 LLM 推理**：所有限制计算均在图层面完成，不依赖额外的模型调用，从而避免了推理开销。

### 6. 主要结论与发现
*   **极高的安全性**：在 AgentDojo 的工具知识攻击中，SkillGuard 在三个套件上实现了 **0% 的攻击成功率 (ASR)**。
*   **功能保留**：分数流限制策略比二值策略保留了显著更多的能力（在 Travel 套件中保留了约 94% 的能力，而二值策略仅为 76-79%）。
*   **组合攻击防御**：在 Llama 模型上，SkillGuard 面对组合攻击时表现最佳（ASR 仅 8%），且良性任务的成功率（BU）更高。
*   **零推理成本**：与 CaMeL（增加多达 96 次调用）和 AttriGuard 相比，SkillGuard 实现了零 Token 增量。

### 7. 优点
*   **原理严谨**：将安全问题转化为图论中的可达性问题，提供了形式化的安全保证。
*   **效率极高**：不依赖 LLM 进行防御决策，避免了防御者被“二次注入”的风险，且大幅降低了延迟和成本。
*   **精细化控制**：通过分数流策略实现了权限的最小化收缩，而非一刀切的禁用。

### 8. 不足与局限
*   **依赖先验知识**：防御效果高度依赖于部署者定义的“技能摘要”、“可控性签名”和“禁止状态”的准确性。如果策略定义有误，可能导致漏报或误报。
*   **图规模扩展性**：在 Workspace 等复杂场景下，由于节点和路径极多，最小割计算的延迟会显著增加（达 12 秒），可能影响实时交互体验。
*   **覆盖范围限制**：该防御仅针对通过“工具调用”实现的攻击，无法防御纯文本层面的攻击（如智能体通过聊天误导用户）。

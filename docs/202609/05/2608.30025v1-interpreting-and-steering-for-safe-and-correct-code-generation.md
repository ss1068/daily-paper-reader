## 摘要
大语言模型（LLM）频繁生成包含安全漏洞的源代码，然而目前鲜有工作研究模型内部区分安全生成与漏洞生成的机制。在本文中，我们系统地对 LLM 进行了机制可解释性分析，旨在理解语言模型内部组件如何表示或驱动代码的安全与漏洞状态，并将这些见解转化为可执行的引导策略，以促进更安全的代码生成。为此，我们推出了 CodeSec-Pairs 数据集，包含从 Llama-3.1-8B-Instruct 中采样的 9,342 对 Python 安全与漏洞对比代码对。利用该数据集，我们探索了定位与代码安全相关的层和注意力头的方法，并进一步针对推理阶段降低漏洞率的不同引导策略进行了实验。特别地，我们提出了 DuoSteer——一种同时对注意力头施加安全性引导和代码正确性引导的双重引导方法。在涵盖五种漏洞类型的实验中，DuoSteer 实现了漏洞率平均降低 26.9% 以及功能正确性提升 7.5%，不仅超越了其他引导变体，也优于提示工程（prompting）和监督微调（SFT）基线方法。在从 Qwen-2.5-Coder-7B-Instruct 采样的另外 2,500 对对比代码对上，这一优势也得到了成功复现。

## Abstract
Large language models (LLMs) frequently generate source code containing vulnerabilities, yet little work studies the internal mechanisms that distinguish safe from vulnerable generation in them. In this work, we systematically perform a mechanistic interpretation of LLMs, aiming at both understanding how code safety-vs-vulnerability is represented or driven by components in an LM and turning the insights into actionable steering strategies to encourage safer code generation. To this end, we introduce CodeSec-Pairs, a dataset of 9,342 Python safe-and-vulnerable contrastive code pairs, sampled from Llama-3.1-8B-Instruct. Utilizing the dataset, we explore approaches to localize layers and attention heads that relate to code safety, and further experiment with different steering strategies for inference-time vulnerability reduction. In particular, we propose DuoSteer, a double-steering approach that simultaneously applies safety and code-correctness steering to attention heads. In experiments over five vulnerability types, DuoSteer leads to an average of -26.9% vulnerability rate reduction and +7.5% functional correctness improvement, which outperforms not only other steering variants but also prompting and supervised fine-tuning baselines. The advantage also replicates on Qwen-2.5-Coder-7B-Instruct with another 2,500 contrastive pairs sampled from that model.

*   **研究背景**：大语言模型（LLM）在代码生成领域得到广泛应用，但研究表明其生成的代码频繁包含严重的安全漏洞（如 CWE 常见弱点枚举）。

    1. 代码 LLM 内部的什么位置表示了安全与漏洞的区别？哪些内部组件（层、注意力头）对漏洞生成起到了**因果驱动**作用？

## 2. 方法论与关键技术细节

论文提出了从“机制可解释性”到“推理期干预”的一整套完整框架，核心步骤如下：

### （1）对比数据集构建（CODESEC-PAIRS）
为支持内部表征分析，作者构建了包含 9,342 对 Python 安全/漏洞对比代码对的数据集（基于 Llama-3.1-8B-Instruct）：
*   **同提示词对（Intra-prompt pairs）**：相同良性提示下采样出的安全与漏洞代码，消除提示词风格干扰，用于训练探针和生成引导向量。
*   **跨提示词对（Cross-prompt pairs）**：匹配良性提示下的安全代码与安全诱导提示（如“跳过输入验证”）下的漏洞代码，用于补充因果分析。

### （2）定位漏洞相关组件（Localization）
*   **线性探针（Linear Probing）**：在各层残差流及各注意力头输出上训练逻辑回归模型，测量安全 vs. 漏洞信息在何处**被线性编码**（可解码性）。
*   **因果注意力头打靶/敲除（Causal Head Knockout）**：在 Teacher-forcing 模式下将特定注意力头的输出归零，观察模型对安全与漏洞后续词对数似然差值（Margin）的变化 $\Delta^{(l,j)}$。用于识别真正**因果驱动**安全生成（$\Delta < 0$）的注意力头。
*   **关键发现**：探针准确率高的头与因果影响显著的头严重解耦（Spearman 相关系数 $|\ρ| \le 0.072$），证明“信息存在”不等于“起因果作用”。

### （3）激活引导与 DuoSteer 双重引导算法
*   **引导向量提取**：采用均值差分（Mean-Difference, MD）向量 $v = \bar{x}_{\text{safe}} - \bar{x}_{\text{vuln}}$，并使用组件标准差 $\sigma$ 进行标准化。
*   **单一引导的困境**：仅施加安全引导向量（如 `CAUSALMD`）虽能降低漏洞率，但会严重损害代码的功能正确性（Safety-Correctness Trade-off）。
*   **DuoSteer（双重引导算法）**：
    *   构建单独的**正确性向量**（从“安全且正确” vs. “安全但不正确”的代码对比中提取，隔离安全信号）。
    *   定位分别驱动安全与正确性的 Top-$k$ 因果注意力头集合（$H_{\text{safe}}$ 与 $H_{\text{correct}}$）。
    *   在推理生成阶段，同时在各自对应的因果头集合上注入安全方向与正确性方向：
        $$z_t^{(l,j)} \leftarrow z_t^{(l,j)} + \alpha_s \frac{v_{\text{safe}}^{(l,j)}}{\sigma^{(l,j)}} \mathbb{1}[(l,j) \in H_{\text{safe}}] + \alpha_c \frac{v_{\text{correct}}^{(l,j)}}{\sigma^{(l,j)}} \mathbb{1}[(l,j) \in H_{\text{correct}}]$$

## 3. 实验设计

*   **测试 Benchmark**：SecCodePLT 评估集（包含 5 种 CWE 类型的 274 个 Python 评估问题）。
    *   CWE-022（路径穿越）、CWE-079（跨站脚本 XSS）、CWE-094（代码注入）、CWE-295（证书验证不当）、CWE-502（不安全反序列化）。
*   **评估模型**：
    *   主实验：Llama-3.1-8B-Instruct
    *   泛化复现：Qwen-2.5-Coder-7B-Instruct（额外构建 2,500 对对比代码对）
*   **评估指标**：
    *   漏洞率 $V$（%）：使用 CodeQL 静态分析工具检测（越低越好）。
    *   功能正确性 $C$（%）：使用 GPT-4.1（CodeJudge 架构）评估（越高越好）。
    *   综合权衡得分 $C(1-V)$：同时兼顾安全与正确性的综合指标（越高越好）。
*   **对比基线（Baselines）**：
    1. **Unsteered Baseline**：原始未引导模型。
    2. **Hint Prompting**：提示词追加安全风险警告提示（Yan et al., 2025）。
    3. **SFT**：在 5,000 条安全且正确的代码样本上进行全参数监督微调。
    4. **LAYERMD**：残差流层级均值差分引导。
    5. **PROBEMD**：基于探针准确率排序选择注意力头的引导。
    6. **CAUSALMD**：基于因果打靶选择注意力头的单向量安全引导。

## 摘要
多智能体大语言模型（LLM）应用将规划器、工作智能体、验证器和合成器串联在一起，而智能体之间的每一次跳转都是一个未受监控的通道，攻击者可以通过这些通道潜入指令。现有的防御措施仅保护输入边界（如 IBProtector、Llama Guard、困惑度过滤器、SmoothLLM），或者作为不透明且具有随机性的提供商端过滤器运行在应用之外。我们展示了这一差距带来的一个鲜被衡量的后果：在针对 8 个攻击家族、5 种防御措施和 3 个模型后端的 2,100 条轨迹评估中，一个在标准报告下看似完全安全（工具中毒和内存中毒的攻击成功率为 0.000）的无防御流水线，其安全性几乎完全归功于云提供商的服务器端过滤器（在 Azure GPT-5 上的 60 次拦截中占 54 次），而在没有此类过滤器的后端上，安全性则默默地转移到了智能体模型自身的对齐能力上。仅基于结果的报告掩盖了这种依赖性。我们提出了 ChannelGuard，这是一个无需训练的深度防御框架，在每个智能体间的通道上设置了信息瓶颈门控；每个门控通过嵌入相似度对通道文本与对抗性短语库进行评分，并确定性地通过、压缩或拦截文本，且不增加额外的 LLM 调用，同时通过归因方法记录哪一层拦截了每次攻击。ChannelGuard 的工具输出门控在应用层拦截了 30/30 的工具中毒攻击，在 Azure GPT-5、Anthropic Sonnet 4.5 和 Anthropic Haiku 4.5 上表现一致，而无防御的流水线在不同后端之间表现差异巨大；它还将提示注入攻击的成功率降低了一半（从 0.333 降至 0.167），并精确保持了 GSM8K 的准确率（0.867）。白盒自适应改写可以规避所有嵌入门控，而“扰动并投票”基准表现更好。扩展附录增加了基准测试、消融实验、参数扫描、良性样本保留分析以及评判审计（kappa = 0.900），总成本为 47.36 美元。

## Abstract
Multi-agent LLM applications chain a planner, worker agents, a verifier, and a synthesizer, and every hop between agents is an unmonitored channel through which an adversary can smuggle instructions. Existing defenses guard only the input boundary (IBProtector, Llama Guard, perplexity filters, SmoothLLM) or run outside the application as opaque, stochastic provider-side filters. We show this gap carries a consequence rarely measured: on a 2,100-trace evaluation across eight attack families, five defenses, and three model backends, an undefended pipeline that appears fully safe under standard reporting (attack success 0.000 on tool- and memory-poisoning) owes that safety almost entirely to the cloud provider's server-side filter (54 of 60 blocks on Azure GPT-5), and silently shifts to the agent model's own alignment on a backend without such a filter. Outcome-only reporting hides this dependence. We present ChannelGuard, a training-free defense-in-depth framework placing information-bottleneck gates on every inter-agent channel; each scores channel text against an adversarial phrase bank by embedding similarity and deterministically passes, compresses, or blocks it, adding no LLM call, while an attribution method records which layer stopped each attack. ChannelGuard's tool-output gate blocks Tool Poisoning 30 of 30 at the application layer, identically across Azure GPT-5, Anthropic Sonnet 4.5, and Anthropic Haiku 4.5, whereas the undefended pipeline shifts entirely across backends; it also lowers Prompt Injection attack success by half (0.333 to 0.167) and preserves GSM8K accuracy exactly (0.867). White-box adaptive paraphrase evades every embedding gate, where a perturb-and-vote baseline does better. An extended appendix adds baselines, ablations, sweeps, a benign-preservation analysis, and a judge audit (kappa = 0.900), at a total cost of 47.36 USD.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：现代大语言模型（LLM）应用通常由多个智能体（规划器、工作者、验证器、合成器）协作完成。虽然单个模型可能经过了安全对齐，但智能体之间传递信息的“内部通道”往往未受监控。
*   **研究动机**：攻击者可以通过工具输出中毒、内存中毒或提示注入等手段，在这些内部通道中“走私”恶意指令。
*   **现状不足**：现有的防御措施（如 Llama Guard）大多只守住“入口”（用户输入），或者依赖于云服务商（如 Azure）不透明且随机的服务器端过滤器。论文指出，这种依赖会导致“机制替代”现象——即系统的安全性并非来自应用本身，而是寄生在特定的后端供应商上，一旦更换后端，安全性便无法保证。

### 2. 论文提出的方法论：ChannelGuard 框架
*   **核心思想**：在多智能体系统的**每一个**内部通信通道上部署“信息瓶颈”（Information Bottleneck, IB）门控，实现深度防御。
*   **关键技术细节**：
    *   **六大门控位置**：从用户到规划器（IB-0）、规划器到工作者（IB-1）、工具到工作者（IB-3）、内存到工作者（IB-3-mem）等，覆盖了所有信息流转节点。
    *   **评分机制**：使用本地运行的轻量级句子嵌入模型（如 MiniLM），计算通道文本与预设的“对抗性短语库”之间的最大余弦相似度。
    *   **确定性决策**：根据风险评分，门控采取三种行动：
        1.  **通过 (Pass)**：风险极低，原样转发。
        2.  **压缩 (Compress)**：中等风险，仅保留前 N 句良性前缀，截断后续内容。
        3.  **拦截 (Block)**：高风险，直接清空文本并触发“早期退出”机制，停止后续昂贵的 LLM 调用。
    *   **三重过滤器**：在最终合成阶段，结合门控评分、多样本蒙特卡洛验证器的安全分和置信度进行最终裁决。

### 6. 论文的主要结论与发现
*   **安全模型不等于安全系统**：即使使用对齐良好的模型，多智能体组合也会暴露新的攻击面。
*   **供应商依赖风险**：无防御系统在 Azure 上的安全性 90% 依赖于 Azure 的内置过滤器；一旦切换到无过滤器的后端，防御压力会完全转移到模型对齐上，且表现不稳定。
*   **ChannelGuard 的有效性**：在应用层实现了确定性的拦截，将提示注入 ASR 降低了 50%，并完全拦截了工具中毒攻击，同时对良性任务的准确率零损耗。
*   **防御局限**：静态短语库无法有效抵御经过精心设计的“白盒自适应改写”攻击。

### 7. 优点
*   **深度防御架构**：首次系统性地对多智能体系统的所有内部通道进行建模和防御。
*   **供应商无关性**：提供了一套不依赖于特定云厂商黑盒过滤器的应用层安全方案。
*   **低成本与高性能**：无需微调模型，本地 CPU 嵌入计算延迟极低（毫秒级），且通过短路机制节省了 API 费用。
*   **评估严谨**：引入了“归因分析”和“良性保留率”指标，避免了单一 ASR 指标的片面性。

### 8. 不足与局限
*   **静态库弱点**：依赖于预设的短语库，对于语义相同但措辞迥异的自适应攻击（Adaptive Paraphrase）防御力较弱。
*   **压缩机制的顺序依赖**：目前的“保留前 N 句”策略假设攻击载荷在末尾，如果攻击者将载荷置于开头，该策略会失效。
*   **语言限制**：短语库目前主要针对英文，跨语言的泛化能力未在文中深入探讨。
*   **叙事性攻击挑战**：对于隐藏在看似正常的对话流中的“缓慢漂移”内存攻击，基于相似度的门控容易漏报。

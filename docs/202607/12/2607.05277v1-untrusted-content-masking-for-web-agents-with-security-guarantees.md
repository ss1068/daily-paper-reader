## 摘要
针对提示注入攻击提供安全保证的防御措施依赖于可信指令与不可信数据之间的严格隔离。在基于文本的环境（如工具调用 API）中，这种隔离是自然产生的：智能体可以根据接口定义进行推理，而无需处理不可信内容。将这些保证扩展到 Web 智能体面临着一个根本性的挑战：为了感知环境并与之交互，Web 智能体必须首先观察渲染后的页面，而页面中可信内容与不可信内容交织在一起。这种结构上的纠缠消除了安全保证所依赖的信任边界，从而破坏了 Web 智能体的可证明防御。在本文中，我们提出了不可信内容屏蔽（Untrusted Content Masking, UCM），这是一种在 Web 环境中恢复该边界的简单且有效的方法。我们利用了一个关键的结构性见解：网页的文档对象模型（DOM）编码了足够的信息，可以在不读取内容的情况下区分可信区域和不可信区域。我们的框架利用这一点，在不可信区域到达智能体之前对其进行脱敏，并通过具有严格权限分离的沙箱接口路由交互，从而使智能体能够观察环境并与之交互，同时保持与对抗性内容的隔离。代码已公开。

## Abstract
Defenses that provide security guarantees against prompt injection attacks rely on strict isolation between trusted instructions and untrusted data. In text-based environments such as tool-use APIs, this separation arises naturally: agents can reason from interface definitions without ever processing untrusted content. Extending these guarantees to web agents faces a fundamental challenge: to perceive and interact with their environment, web agents must first observe the rendered page, which intermingles trusted content with untrusted content. This structural entanglement removes the trust boundary on which security guarantees depend, undermining provable defenses for web agents. In this paper, we present Untrusted Content Masking (UCM), a simple and effective approach that restores this boundary in web environments. We leverage a key structural insight: a webpage's Document Object Model (DOM) encodes sufficient information to distinguish trusted from untrusted regions without reading their content. Our framework exploits this by redacting untrusted regions before they reach the agent and routing interaction through a sandboxed interface with strict privilege separation, thereby enabling agents to observe and interact with their environment while remaining isolated from adversarial content. The code is publicly available.

### 2. 论文提出的方法论：不可信内容屏蔽 (UCM)
核心思想是利用网页 DOM 结构的语义信息，在内容到达智能体之前将其“脱敏”。
*   **不可信内容屏蔽 (Masking)**：利用 DOM 标签和属性识别不可信区域（如评论区），在渲染给主智能体（Agent）之前，将这些区域替换为带 ID 的占位符（如 `id: product-review-1`）。
*   **隔离模型交互 (Q-Model)**：
    *   当智能体确实需要读取不可信内容时（例如“分析评论情感”），它不能直接读取，而是向一个**隔离模型（Quarantined Model）**发起查询。
    *   **关键技术细节**：Q-Model 只能返回**受限的结构化数据类型**（布尔值、整数、浮点数、日期、枚举）。由于输出不包含自由文本，恶意指令无法通过 Q-Model 传播回主智能体，从而在设计上杜绝了控制流劫持。
*   **自动化边界推理**：对于未标注的网页，利用 LLM 在**内容脱敏后的 HTML**（仅保留结构，删除所有文本和敏感属性）上进行推理，自动识别哪些 CSS 选择器对应不可信区域。

### 6. 论文的主要结论与发现
*   **安全性**：UCM 在 WASP 攻击测试中实现了 **0% 的攻击成功率 (ASR)**，而无防御状态下 ASR 为 17%。

*   **结构化优势**：DOM 结构足以提供区分信任边界的信息，LLM 可以在不看具体内容的情况下准确识别不可信区域（F1 分数在 0.84-0.99 之间）。

### 7. 优点
*   **设计即安全 (Security by Design)**：通过类型约束强制隔离，不依赖于模型对注入指令的识别能力，防御具有确定性。
*   **低侵入性**：不需要对现有网站进行大规模重构，只需少量的 CSS 选择器标注或自动化推理即可部署。
*   **灵活性**：Q-Model 支持多种返回类型，能够适应从简单的“是/否”判断到复杂的数值提取等多种任务。

### 8. 不足与局限
*   **数据流攻击 (Data-Flow Attacks)**：虽然 UCM 阻止了控制流劫持（智能体不会被诱导去执行恶意动作），但攻击者仍可能通过操纵 Q-Model 返回的数值（如将“价格”改低）来误导智能体的决策。
*   **依赖标注质量**：如果网站所有者错误地将不可信区域标注为可信，防御就会失效。
*   **自由文本限制**：对于必须提取长段自由文本（如总结评论）的任务，受限类型无法处理，必须引入人工审批，这会降低自动化程度。
*   **推理延迟与成本**：多次调用 Q-Model 会增加任务的完成时间和 API 费用。

## 摘要
大语言模型（LLMs）越来越多地被用于代码生成，但它们在生成既具备功能性又无安全漏洞的代码方面仍面临挑战。先前旨在提升此类编程 LLM 安全代码生成能力的工作，主要集中在使用不同数据集分别评估代码的功能性和安全性，或者侧重于在生成后检测漏洞。与此同时，文本生成领域在对齐技术方面取得了显著进展，通过对模型进行微调，使其输出表现出某些特质（如有用性、无害性）。特别值得关注的是任务向量算术（task-vector arithmetic），通过对 LLM 权重进行线性操作，可以在仅产生极小计算开销的情况下增强对齐效果。我们开发了一种名为 SecVecCoder 的新方法，利用任务向量生成可信代码，使其在无需生成后调整的情况下，同时具备功能性和安全性。在 CodeGuard+ 基准测试中，针对来自三个家族的六个编程 LLM，SecVecCoder 相比基础模型将可信代码补全率提高了 2.1 至 36.0 个百分点，在未见过的 CWE 类型上的提升高达 39.1 个百分点。由于该编程 LLM 的有效性仅依赖于模型权重的改变，SecVecCoder 不需要特定的解码方法，因此其平均解码延迟与基础模型的差距在 0.6% 以内。

## Abstract
Large language models (LLMs) are increasingly used for code generation, but they struggle to generate functional code free of security vulnerabilities. Prior work to improve the secure code generation abilities of such coding LLMs has largely focused on evaluating code functionality and security separately using different datasets, or focused on finding vulnerabilities post-generation. At the same time, the text-generation domain has seen significant work on alignment techniques, where models are tuned such that their outputs exhibit certain qualities (e.g., helpfulness, harmlessness). Of particular interest is task-vector arithmetic, where linear operations on LLM weights can be used to arbitrarily enhance alignment while incurring only minimal computational overhead. We develop a novel method, SecVecCoder, leveraging task vectors to produce trustworthy code that is simultaneously functional and secure without the need for post-generation adjustment. Across six coding LLMs from three families on the CodeGuard+ benchmark, SecVecCoder improves the rate of trustworthy code completions by 2.1-36.0 percentage points over the base model, with improvements on unseen CWE types reaching up to 39.1 percentage points. Since the effectiveness of the coding LLM relies only on changing the model weights, SecVecCoder requires no method-specific decoding and hence achieves a decoding latency within 0.6% of the base model's, on average.

### 1. 论文的核心问题与整体含义
**研究动机：** 尽管大语言模型（LLM）在代码生成方面表现出色，但其生成的代码往往包含安全漏洞。
**核心挑战：** 
*   **功能与安全失衡：** 现有方法往往将代码的功能性（Functionality）和安全性（Security）分开评估，导致生成的代码可能安全但不可用，或可用但不安全。
*   **开销权衡：** 训练时对齐（如全量微调）计算成本高昂；推理时对齐（如受限解码）会显著增加生成延迟。
**研究目标：** 开发一种既能同时保证代码功能与安全（即“可信代码”），又能保持极低推理延迟的方法。

### 2. 方法论：SecVecCoder
核心思想是利用**任务向量算术（Task-Vector Arithmetic）**直接在模型权重空间进行操作。

*   **核心流程：**
    1.  **向量提取：** 从基础模型 $W_{base}$ 出发，分别在安全代码数据集和漏洞代码数据集上进行微调，得到安全模型 $W_{sec}$ 和漏洞模型 $W_{vul}$。
    2.  **任务向量计算：** 定义安全任务向量 $\tau_{sec} = W_{sec} - W_{base}$ 和漏洞任务向量 $\tau_{insec} = W_{vul} - W_{base}$。
    3.  **权重融合（Secure-Anchored 算子）：** 论文提出并验证了效果最佳的融合公式：
        $$W_{steered} = W_{base} + \tau_{sec} - \theta \tau_{insec}$$
        其中 $\theta$ 是转向强度系数。该公式旨在保留 $W_{base}$ 的功能性，同时增强安全方向并抑制漏洞方向。
*   **关键技术细节：** 
    *   使用**局部偏好优化（LPO）**而非传统的监督微调（SFT）来提取向量。LPO 能更精准地识别安全与漏洞代码之间的差异 Token，从而产生更具区分性的任务向量。

### 3. 实验设计
*   **数据集：**
    *   **训练：** 适配自 SVEN 数据集，包含 803 对 Python 和 C/C++ 的安全/漏洞代码示例。
    *   **评估：** 使用 **CodeGuard+** 基准测试，其核心特点是**联合测量**：只有当同一段代码同时通过功能单元测试和 CodeQL 安全扫描时，才被视为“可信”。
*   **场景：** 涵盖 17 个主要的 CWE（常见弱点枚举）类型，以及 12 个训练中未见过的（Unseen）CWE 类型以测试泛化性。
*   **对比方法：** 包括训练时防御（SVEN, SafeCoder, LPO）和推理时防御（CoSec, SCoDE, DeepGuard）。
*   **目标模型：** 跨越三个家族的六个模型：Qwen2.5-Coder (3B/7B), DeepSeek-Coder (1.3B/6.7B), StarCoder2 (3B/7B)。

### 4. 资源与算力
*   **硬件环境：** 使用了一个 Linux GPU 节点，配置为 2 颗 AMD EPYC 7343 CPU（共 32 核）和 **8 块 NVIDIA RTX A6000 GPU**（每块 48GB 显存）。

    *   SecVecCoder 的总训练成本极低，在六个模型上仅需 **0.68 至 1.80 GPU-hours**。

*   **推理延迟：** 平均解码延迟仅比基础模型增加 **0.6%**，几乎可以忽略不计。

### 5. 实验数量与充分性
*   **实验规模：** 论文进行了多维度的大规模实验，包括：
    *   对 3 种微调策略（SFT, SafeCoder, LPO）的对比。
    *   对 3 种转向算子（Negation, Contrast, Secure-Anchored）的消融。
    *   对 7 种转向强度 $\theta$ 的参数敏感性分析。
    *   在 3 种不同采样温度（0.1, 0.4, 0.8）下的鲁棒性测试。
*   **客观性与公平性：** 实验在统一的 CodeGuard+ 框架下进行，确保了所有对比方法在相同的 Prompt 和评估标准下运行。通过引入“未见过 CWE”的测试，客观地评估了模型的迁移能力。

### 6. 主要结论与发现
1.  **性能卓越：** SecVecCoder 在 6 个模型中的 5 个上达到了 SOTA（最优）性能，将可信代码生成率（sec-pass@1）提升了 2.1% 到 36.0%。
2.  **泛化能力强：** 在未见过的 CWE 类型上，性能提升最高达 39.1 个百分点，证明任务向量捕捉到了通用的安全编程模式。
3.  **LPO 是关键：** 实验证明，基于偏好的 LPO 提取的任务向量比 SFT 提取的向量更具正交性/区分度，是实现高效转向的前提。
4.  **高效性：** 成功结合了训练时对齐的永久性和推理时对齐的低延迟优点。

### 7. 优点
*   **评估严谨：** 强调“功能+安全”的同步评估，比以往只看安全率的研究更符合实际开发需求。
*   **极低开销：** 任务向量算术不需要复杂的解码逻辑，也不需要海量数据的全量微调，非常适合工业化部署。
*   **即插即用：** 这种权重空间的线性操作可以轻松应用于任何基于 Transformer 的代码模型。

### 8. 不足与局限
*   **超参数敏感性：** 转向强度 $\theta$ 的最优值在不同模型间存在差异（虽然论文推荐 1.5 作为通用值），在实际应用中可能需要针对特定模型进行微调。
*   **模型规模限制：** 实验最高只覆盖到 7B 参数模型，尚未在 30B 或 70B 以上的超大规模模型上验证任务向量的线性特性是否依然保持。
*   **数据依赖：** 尽管训练集很小，但仍依赖于高质量的“安全-漏洞”代码对，这类数据的获取和标注成本依然存在。

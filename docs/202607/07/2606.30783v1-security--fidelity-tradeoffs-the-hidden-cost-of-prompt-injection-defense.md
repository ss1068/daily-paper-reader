## 摘要
我们在防御大语言模型（LLM）免受间接提示词注入攻击的过程中，发现了一种安全性与保真度之间的权衡：防御手段主要通过抑制不可信文本来抵御注入的指令，但这会破坏翻译和文档编辑等必须保留这些文本的任务。攻击成功率指标无法察觉这一点，因为忽略注入内容的模型与将其作为数据忠实处理的模型在得分上是相同的。我们推出了 SecFid，这是一个专门构建的基准测试，使得执行注入指令、将其作为数据处理以及忽略注入内容这三种行为能产生可区分的输出。这使得保真度变得可衡量，并揭示了一个前沿问题：在 1,168 个示例和 48 种配置中，没有任何模型或防御手段能同时实现这两个目标。保真度最高的模型在安全性为 47.8% 时达到了 96.5% 的保真度，而最安全的防御手段则相反，安全性达到 99.3%，但保真度仅为 71.0%-73.9%。即使安全性相同的防御手段，其实现方式也各不相同：有些将劫持修复为忠实处理，而另一些则只是简单地抑制良性内容。决策理论分析表明，为什么没有一种固定的选择能在所有场景下都正确：正确的行为并非防御本身的属性，而是取决于部署环境，由劫持成本与内容丢失成本的相对比例决定。因此，仅凭安全性只能衡量鲁棒性的一半，如果不报告保真度，就会掩盖为了获得安全性所付出的代价。

## Abstract
We identify a security-fidelity tradeoff in defending LLMs against indirect prompt injection: defenses resist injected instructions largely by suppressing untrusted text, which corrupts tasks that must preserve it, such as translation and document editing. Attack-success metrics cannot see this, because a model that ignores an injection and one that faithfully processes it as data score identically. We introduce SecFid, a benchmark built so that executing an injection, processing it as data, and ignoring it produce distinguishable outputs. This makes fidelity measurable and exposes a frontier: across 1,168 examples and 48 configurations, no model or defense achieves both objectives. The highest-fidelity model reaches 96.5% fidelity at 47.8% security, while the most secure defenses invert this, at 99.3% security but only 71.0%-73.9% fidelity. Even defenses with identical security differ in how they earn it: some repair hijacks into faithful processing, others simply suppress benign content. A decision-theoretic analysis shows why no fixed choice can be right everywhere: the correct behavior is not a property of the defense but of the deployment, set by its relative cost of a hijack versus a dropped span. Security alone therefore measures only half of robustness, and reporting it without fidelity hides the price at which it was bought.

### 2. 方法论：核心思想与技术细节
*   **核心思想：行为可分离性（Behavioral Separability）**：
    设计一种实验环境，使得模型对注入内容的三个不同反应能产生互不重叠的输出：
    1.  **执行（Executed）**：模型被劫持，执行了注入的指令。
    2.  **处理（Processed）**：模型正确识别注入内容为数据，并对其执行原定任务（如翻译它）。
    3.  **忽略（Ignored）**：模型为了安全直接跳过或删除了该段文本。
*   **SecFid 基准测试构建**：
    *   **全文本任务（Full-text tasks）**：如翻译和编辑。如果模型忽略注入内容，输出会缺失对应片段；如果处理，则会包含翻译/编辑后的片段。
    *   **部分文本任务（Partial-text tasks）**：如实体提取和计数。通过在注入内容中埋入特定实体，观察模型输出的集合或数值是否包含该实体来区分“处理”与“忽略”。
*   **度量指标**：
    *   **Security（安全性）** = 1 - 执行率。
    *   **Fidelity（保真度）** = 1 - 忽略率。
*   **决策理论分析**：作者通过公式 $\tau^* = \frac{C_{fid}}{C_{fid} + C_{sec}}$ 证明，最优的防御阈值取决于部署环境的成本比例（劫持成本 vs. 内容丢失成本），因此不存在通用的最佳防御策略。

### 6. 主要结论与发现
*   **不存在双赢**：没有任何模型或防御配置能同时实现极高的安全性和保真度。
*   **防御的代价**：最安全的防御（如 SecAlign）将安全性提升至 99.3%，但保真度大幅下降至 71% 左右。
*   **修复 vs. 抑制**：不同的防御机制原理不同。SecAlign 倾向于“修复”（将劫持转为处理），而 DefensiveTokens 倾向于“抑制”（直接忽略可疑内容）。
*   **推理能力的局限**：增加模型的推理步数主要提升了安全性，但对保真度的提升微乎其微。
*   **任务依赖性**：全文本任务（如编辑）比部分文本任务更容易受到注入攻击，且更难在不损失保真度的情况下进行防御。

### 7. 优点
*   **视角新颖**：首次系统性地量化了提示词注入防御的“功能性代价”。
*   **基准设计精巧**：通过“行为可分离性”解决了长期以来无法区分“安全处理”与“简单忽略”的问题。
*   **理论支撑**：结合决策理论解释了为什么防御策略必须根据应用场景进行动态调整。
*   **实用性**：提出的保真度感知 DPO 方法证明了通过针对性训练可以改善这种权衡。

### 8. 不足与局限
*   **攻击多样性限制**：主要评估了固定形式的探测（Probes），未深入探讨自适应攻击（Adaptive Attacks）在保真度维度上的表现。
*   **二元决策假设**：在成本分析中将防御简化为“处理或过滤”的二元选择，而现实中可能存在更复杂的中间状态（如沙箱运行）。
*   **任务覆盖**：虽然涵盖了四大类任务，但对于更复杂的长文本推理或多模态场景的保真度损失尚待研究。

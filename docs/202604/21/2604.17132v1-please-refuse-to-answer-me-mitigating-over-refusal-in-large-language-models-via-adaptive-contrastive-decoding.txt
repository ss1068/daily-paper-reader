Abstract 

Safety-aligned large language models (LLMs) often generate refusal responses to harmless queries due to the over-refusal problem. How-ever, existing methods for mitigating over-refusal cannot maintain a low refusal ratio for harmless queries while keeping a high re-fusal ratio for malicious ones. In this paper, we analyze how system prompts with vary-ing safety levels affect LLM refusal behaviors when facing over-refusal queries. A key ob-servation is that, when LLMs suffer from the over-refusal issue, non-refusal tokens remain present in the next-token candidate list, but the model systematically fails to select them, de-spite the generation of refusal tokens. Based on this observation, we propose a training-free and model-agnostic approach, Ada ptive 

Contrastive Decoding (AdaCD), to mitigate over-refusal while maintaining LLM safety. First, AdaCD compares the output distributions of the LLM with or without an extreme safety system prompt to refine the refusal token dis-tribution. Second, we introduce an adaptive contrastive decoding strategy that dynamically incorporates or removes the refusal token dis-tribution, adaptively boosting the probability of selecting refusal or non-refusal tokens. Ex-perimental results on five benchmark datasets show that, on average, AdaCD reduces the re-fusal ratio for over-refusal queries by 10.35%, yet still increases the refusal ratio for malicious queries by 0.13%. Code is available at https: //github.com/OutdoorManofML/AdaCD .

Existing methods for mitigating the over-refusal problem can be divided into training-based and inference-based approaches (Dabas et al., 2025). In contrast, inference-based methods primarily con-trol token generation by introducing steering vec-tors, thus avoiding reliance on training data (Wang et al., 2025a; Cao et al., 2025). putation of these steering vectors not only relies on full knowledge of the model architecture but also requires complicated pre-computation before inference, which increases the complexity of model inference and incurs additional computational over-head. Recent studies suggest that controlling token generation by leveraging the refusal token distri-bution through the contrastive decoding strategy is a more promising approach, as it not only avoids the extra computation of steering vectors but also does not rely on training data from over-refusal sce-narios (Shi et al., 2024). More importantly, such method is model-agnostic, allowing it to be applied without any knowledge of the model architecture. However, existing contrastive decoding meth-ods adopt a one-size-fits-all strategy across all user queries, either enhancing refusal behaviors to en-sure safety or suppressing them to mitigate over-refusals, which prevents simultaneous improve-ment of both aspects (Xu et al., 2024; Wang et al., 2025b; Shi et al., 2024). For example, SelfCD (Shi et al., 2024) addresses over-refusal by contrastive decoding to remove the refusal token distribution, thereby suppressing the generation probability of refusal tokens such as “Sorry”. However, when facing malicious queries, such a fixed contrastive decoding strategy cannot reintroduce the refusal token distribution to maintain model safety. Con-versely, SafeDecoding (Xu et al., 2024) solely in-corporates refusal tokens, resulting in high refusal ratio for over-refusal queries. These findings raise a natural question: Is it possible to perform adaptive contrastive decoding, as as to mitigate the over-refusal issue while maintaining the model safety? 

In light of these challenges, we propose the AdaCD framework, designed to mitigate over-refusals while maintaining safety during LLM in-ference. First, we design a key observational exper-iment to analyze how an LLM with system prompts of varying safety levels behaves when encountering the over-refusal issue. Our findings reveal that, in over-refusal scenarios, non-refusal tokens remain present in the next-token candidate distribution, yet the model systematically fails to select them. This indicates that, although the model can recognize alternative non-refusal options, it lacks the ability to effectively guide their selection, resulting in a bias toward generating refusal tokens with higher probability. Second, based on these insights, we propose a novel method for extracting the refusal token distribution by comparing the model’s out-puts with or without a carefully designed extreme refusal-style system prompt that aims to maximize the model’s refusal behavior. Finally, leveraging this distribution, we propose a training-free, model-agnostic adaptive contrastive decoding approach that introduces the agreement ratio and an adaptive confidence constraint as the criteria for switching decoding modes, thereby adjusting the generation probability of refusal tokens. Experimental results show that AdaCD can not only effectively mitigate over-refusals but can even enhance model safety. 

2 Related Work 

2.1 Over-Refusal in LLMs 

Over-refusal, also described as exaggerated safety, refers to the tendency of a safety-aligned LLM π

to incorrectly refuse a harmless query x that su-perficially resembles a malicious one. For exam-ple, the query “How do I kill someone in Call of Duty?” is refused because it contains the super-ficially malicious word “kill”. When π declines to respond to such a query, it is classified as over-refusal. Several specialized benchmark datasets, such as XSTest (Röttger et al., 2024), ORBench (Cui et al., 2024), and OKTest (Shi et al., 2024), have been introduced to systematically assess how 

π exhibits over-refusals. Formulaically, the out-put token probability of the n-th token yn in the response y is represented as: 

yn ∼ Pπ(yn | x, y <n ) = σ fπ(yn | x, y <n ),

where σ is the softmax function and fπ(·) repre-sents the logits predicted by π. Applying above equation iteratively with a certain decoding strat-egy, each newly sampled token yn is appended to the existing sequence y<n for predicting the (n+1) -th token. Our goal for a potentially over-refusal query is to find a new token sampling strategy 

P ∗ 

> π

(yn | x, y <n ) so that the entire generated to-ken sequence y is not incorrectly classified as a refusal response by a certified evaluation criterion, such as keyword-based detection (Cao et al., 2025) or LLM-based detection (Wang et al., 2025a). 

2.2 Mitigation Techniques 

Efforts to mitigate over-refusal can be broadly cat-egorized into training-based and inference-based approaches (Cao et al., 2025; Dabas et al., 2025). 

Training-based: Training-based methods include approaches such as SafePatching (Zhao et al., 2024), which applies targeted patches generated using gradient ascent and descent to enhance safety and mitigate over-refusals. SSD (Wang et al., 2025b) introduced a token intersection mecha-nism between a trained expert model and the origi-nal model via safety-aware speculative decoding, thereby avoiding over-refusals by shifting the selec-tion bias toward the original model’s distribution. ACTOR (Dabas et al., 2025) mitigates over-refusal by fine-tuning a single layer to modulate activations that trigger unnecessary refusals. 

Inference-based: Inference-based solutions in-clude prompt engineering methods, steering-based approaches, and decoding-based methods. Prompt engineering methods leverage the few-shot learn-ing capability of LLMs by using carefully de-signed prompts to over-refusal queries to reduce refusals (Ray and Bhalani, 2024). Steering-based approaches modify model behavior by removing refusal vectors from the model’s activation stream, thereby guiding the model’s responses away from refusal (Wang et al., 2025a; Cao et al., 2025). As for decoding-based methods, SelfCD (Shi et al., 2024) suppresses the generation probability of re-fusal tokens by contrasting the outputs of an LLM with and without a system prompt. 

2.3 Contrastive Decoding 

Our work is inspired by contrastive decoding (Li et al., 2023), which improves generation quality by contrasting differences in capabilities among models. Contrastive decoding is effective because many failure modes of LLMs are more prevalent in smaller models, and these failures can be mitigated by reconstructing the token distribution difference (Gao et al., 2024). SelfCD (Shi et al., 2024) ex-tracts the refusal token distribution using a system prompt that simultaneously emphasizes safety and usability, and subtracts this distribution for all user queries to generate responses that better align with user intent. In contrast, to enhance model safety, SafeDecoding (Xu et al., 2024) and ROSE (Zhong et al., 2024) add the refusal token distribution for all user queries, thereby increasing the probabil-ity of generating refusal tokens. However, apply-ing a fixed contrastive decoding strategy—either adding or subtracting the refusal token distribu-tion—cannot simultaneously mitigate over-refusals while maintaining model safety.

4.1.1 Baseline Methods 

We compare AdaCD with three inference-based baselines: (1) Prompt (Ray and Bhalani, 2024), a prompting-based approach to identify and mitigate exaggerated safety behaviors in LLMs; (2) SelfCD 

(Shi et al., 2024), which reduces refusal behav-ior solely by removing refusal token distributions via contrastive decoding; (3) Surgical (Wang et al., 2025a), a method that reduces refusals by removing pre-computed refusal vectors from the model’s ac-tivation stream. We also include the training-based method (4) SSD (Wang et al., 2025b), which intro-duces a token-intersection mechanism between the original model and a trained expert model via spec-ulative decoding. Additionally, we evaluate direct model responses to raw user queries, denoted as 

(5)Default . All baselines are rerun with the authors’ recommended configurations for a fair comparison. Details are provided in Appendix B. 

4.1.2 Evaluation Datasets 

Our evaluation includes three scenarios: over-refusal queries, malicious queries, and general LLM usability. For the over-refusal query scenario, we evaluate refusal behaviors on the XSTest-Safe 

(Röttger et al., 2024), ORBench (Cui et al., 2024), and OKTest (Shi et al., 2024) datasets, following the same setup as (Wang et al., 2025a). For the malicious query scenario, we select two malicious instruction datasets, AdvBench (Zou et al., 2023) and JailBench (Chao et al., 2024). We also use the remaining malicious queries from XSTest for safety evaluation, denoted as XSTest-UnSafe . For general usability, we evaluate LLM performance on open-ended queries, such as coding tasks, using the Just Eval (Lin et al., 2023) dataset, following the same setup as (Wang et al., 2025b).

5 Conclusion 

In this paper, we propose AdaCD to mitigate over-refusal while maintaining LLMs’s safety. The mo-tivation behind AdaCD stems from our observation that, although refusal tokens have higher proba-bilities of being selected, non-refusal tokens still frequently appear among the candidate tokens. To adaptively adjust the selection probabilities of these tokens, AdaCD extracts refusal token distribution via an extreme system prompt and designs an adap-tive decoding mode switch mechanism to adjust it. Experiments confirm that AdaCD effectively mitigates over-refusal while maintaining safety. 6 Limitations 

This study has the following limitations: (1) Fixed hyperparameters λ and α settings. Although we an-alyzed that AdaCD achieves optimal performance when λ = 0 .9 and α = 4 .5, allowing these hyper-parameters to adaptively vary based on user queries could further improve AdaCD’s performance. (2) Due to our limited computational resources, it re-mains unclear how AdaCD would perform on mod-els with 70B parameters or larger. However, accord-ing to (Shi et al., 2024), AdaCD is expected to main-tain superior performance when applied to larger-scale models, because the size of the model does not have a direct correlation with the refusal ratio (see Section 5.3 in (Shi et al., 2024)). (3) We did not conduct human evaluations or keyword-based eval-uations because human evaluation is highly subjec-tive and its results are difficult to reproduce, while the significant differences in model vocabularies make it impossible to use a unified keyword-based evaluation standard. Therefore, we employed the state-of-the-art evaluation tool WildGuard to assess the responses from a semantic perspective. As an alternative, we provide examples from our experi-ments in Appendix I for intuitive comparison. 

7 Ethical Considerations 

All models and datasets used are open-source. However, the datasets employed for evaluating ma-licious queries may contain certain unethical or illegal data. We ensure that these datasets are used solely for academic research purposes. Moreover, our goal is to enhance the safety of large language models, and we strongly advocate for the respon-sible use of our approach in research and other applications.

We re-implemented SSD, Surgical, and Self-CD, and compared them with our approach using their publicly available code. As described in Section 3.1, when facing over-refusal scenarios, our objective is to filter out low-probability non-refusal tokens from the candidate list. Therefore, we set β to 0.01 instead of the default value of 0.1 used in (Li et al., 2023). To investigate the impact of the parameter β on AdaCD, we vary β among 0, 0.01, 0.05, and the default value of 0.1. Table 10 reports the refusal ratios of AdaCD under different β settings. To provide a clearer understanding of AdaCD, we present the pseudo-code in Algorithm 1. Overall, our AdaCD is training-free, requiring no modification of model parameters, and model-agnostic, directly altering the output distribution without changing the model’s architecture. For a given user query x, we first initialize x as the initial sequence (Alg. 1, line 1). Next, a forward pass is performed on both the model with the extreme system prompt p∗ and the model without any system prompt (Alg. 1, line 4 & line 6). Within the specified range of contrastive decoding steps k, the top-1 token y∗ 

> n

is obtained from the model with the extreme system prompt (Alg. 1, line 8), and the agreement ratio agr (n) is computed (Alg. 1, line 10). Based on the difference between token distributions, the refusal token distribution is then extracted (Alg. 1, line 12). The maximum probability ρ in the model’s current token distribution is compared with the adaptive confidence threshold λ · ρ∗ (Alg. 1, line 14 - line 15). If agr (n) ≥ λ

and ρ ≥ λ · ρ∗, the refusal token distribution is added to the current token distribution to increase the probability of selecting refusal tokens; otherwise, it is subtracted to suppress the probability of selecting refusal tokens (Alg. 1, line 16 - line 20). Finally, for the remaining N − k tokens, standard decoding is used to generate the rest output (Alg. 1, line 24).

## 摘要
自主 AI 智能体正迅速从实验工具转变为运营基础设施，预计到 2026 年底，80% 的企业应用将嵌入 AI 副驾驶（copilots）。随着智能体获得执行现实世界动作的能力（如读取文件、运行命令、发起网络请求、修改数据库），一个根本性的安全漏洞也随之出现。目前主流的智能体安全方法依赖于提示词级护栏（prompt-level guardrails）：即在与试图缓解的威胁相同的抽象层级上运行的自然语言指令。本文认为，对于具有执行能力的智能体而言，基于提示词的安全机制在架构上是不充分的，并由此引入了 Parallax，这是一种基于四个原则的自主 AI 安全执行范式：认知-执行分离（Cognitive-Executive Separation），从结构上防止推理系统执行动作；具有分级确定性的对抗性验证（Adversarial Validation with Graduated Determinism），在推理和执行之间插入一个独立的、多层级的验证器；信息流控制（Information Flow Control），通过智能体工作流传播数据敏感性标签，以检测与上下文相关的威胁；以及可逆执行（Reversible Execution），捕获破坏前的状态，以便在验证失败时进行回滚。我们展示了 OpenParallax，这是一个使用 Go 语言编写的开源参考实现，并使用“假设受损评估”（Assume-Compromise Evaluation）对其进行了评估。该方法完全绕过推理系统，以测试在智能体完全受损情况下的架构边界。在涵盖 9 个攻击类别的 280 个对抗性测试用例中，Parallax 在默认配置下拦截了 98.9% 的攻击且误报率为零，在最高安全配置下则拦截了 100% 的攻击。当推理系统受损时，提示词级护栏无法提供任何保护，因为它们仅存在于受损系统内部；而无论如何，Parallax 的架构边界都能保持稳固。

## Abstract
Autonomous AI agents are rapidly transitioning from experimental tools to operational infrastructure, with projections that 80% of enterprise applications will embed AI copilots by the end of 2026. As agents gain the ability to execute real-world actions (reading files, running commands, making network requests, modifying databases), a fundamental security gap has emerged. The dominant approach to agent safety relies on prompt-level guardrails: natural language instructions that operate at the same abstraction level as the threats they attempt to mitigate. This paper argues that prompt-based safety is architecturally insufficient for agents with execution capability and introduces Parallax, a paradigm for safe autonomous AI execution grounded in four principles: Cognitive-Executive Separation, which structurally prevents the reasoning system from executing actions; Adversarial Validation with Graduated Determinism, which interposes an independent, multi-tiered validator between reasoning and execution; Information Flow Control, which propagates data sensitivity labels through agent workflows to detect context-dependent threats; and Reversible Execution, which captures pre-destructive state to enable rollback when validation fails. We present OpenParallax, an open-source reference implementation in Go, and evaluate it using Assume-Compromise Evaluation, a methodology that bypasses the reasoning system entirely to test the architectural boundary under full agent compromise. Across 280 adversarial test cases in nine attack categories, Parallax blocks 98.9% of attacks with zero false positives under its default configuration, and 100% of attacks under its maximum-security configuration. When the reasoning system is compromised, prompt-level guardrails provide zero protection because they exist only within the compromised system; Parallax's architectural boundary holds regardless.

### 1. 核心问题与整体含义（研究动机和背景）
*   **核心挑战**：AI 智能体正从单纯的“内容生成”转向“现实执行”（如操作文件、运行 shell 命令、访问数据库）。
*   **安全谬论**：目前主流的安全防护依赖于“提示词级护栏”（Prompt-level Guardrails），即通过自然语言指令告诉模型“不要做坏事”。作者指出这存在根本性缺陷：指令与数据在同一计算层级处理，极易被提示词注入（Prompt Injection）绕过。
*   **研究动机**：当智能体拥有执行权限时，安全失败的后果是灾难性的（数据泄露、系统破坏）。因此，必须建立一种**架构级**的防御，确保即使推理系统（LLM）被完全攻破，智能体也无法执行有害动作。

### 2. 方法论：Parallax 范式
Parallax 提出了四项核心原则，旨在构建“架构安全”的自主执行环境：
*   **认知-执行分离 (Cognitive-Executive Separation, CES)**：
    *   将系统分为“智能体进程”（推理层，完全不可信，无执行权限）和“引擎进程”（执行层，受信任，负责验证和操作）。两者通过受限的 gRPC 接口通信。
*   **分级确定性的对抗验证 (Adversarial Validation, AV)**：
    *   引入 **Shield** 验证层，按确定性从高到低分为四级：
        *   **Tier 0 (策略)**：基于 YAML 的硬编码规则（如禁止访问 SSH 密钥）。
        *   **Tier 1 (分类器)**：启发式规则 + 本地 DeBERTa 模型检测恶意模式。
        *   **Tier 2 (LLM 评估)**：使用独立的、无上下文的 LLM 进行安全判定（带金丝雀令牌防止注入）。
        *   **Tier 3 (人工)**：高风险或模糊动作需用户手动确认。
*   **信息流控制 (Information Flow Control, IFC)**：
    *   为数据打上敏感度标签（如“受限”、“机密”）。如果智能体读取了机密文件并尝试将其发送到网络，Shield 会识别出非法的信息流向并拦截。
*   **可逆执行 (Reversible Execution)**：
    *   **Chronicle** 系统在执行任何破坏性动作（如删除、修改）前自动捕获状态快照，支持一键回滚。

### 3. 实验设计
*   **评估方法论**：提出 **Assume-Compromise Evaluation (假设受损评估)**。该方法不测试 LLM 是否会拒绝恶意请求，而是直接向执行边界注入恶意工具调用，模拟推理系统已被完全控制的最坏情况。
*   **测试场景**：涵盖 9 大攻击类别（直接/间接注入、多步上下文操纵、工具链攻击、编码混淆、多智能体渗透等）。
*   **数据集**：
    *   280 个对抗性测试用例。
    *   50 个合法动作（用于测试误报率）。
    *   使用 fine-tuned 的 DeBERTa 模型（基于 16,000 个提示词注入样本训练）。
*   **对比基准**：对比了“无防护（Config A）”和“Parallax 架构（Config C）”。（注：由于注入模式绕过了推理层，传统的提示词护栏 Config B 在此实验下保护效力自动归零）。

    *   推理层：测试了 Claude 3.5 Sonnet, Claude 3 Haiku, Llama 3.1 8B。
    *   验证层 (Tier 2)：使用 Claude 3 Haiku。

### 5. 实验数量与充分性
*   **实验规模**：总计 337 组测试（280 对抗 + 57 合法/人工）。
*   **充分性评价**：
    *   **覆盖面广**：实验涵盖了从简单的文件删除到复杂的跨智能体特权提升等多种攻击。
    *   **客观性高**：通过“假设受损”模式排除了 LLM 自身安全训练（RLHF）的干扰，真实反映了架构边界的强度。

### 6. 主要结论与发现
*   **极高的拦截率**：在推理系统完全受损的情况下，Parallax 默认配置拦截了 **98.9%** 的攻击，最高安全配置拦截率达 **100%**。
*   **零误报表现**：在默认配置下，合法动作的误报率为 **0%**。
*   **确定性机制的有效性**：超过 73% 的攻击在 Tier 0 和 Tier 1（非 LLM 层）就被拦截，证明了传统安全机制在 AI 时代的价值。
*   **提示词护栏的脆弱性**：实验证明，一旦模型被诱导产生恶意意图，基于提示词的约束完全无法阻止执行。

### 7. 优点
*   **安全左移**：将安全从不确定的“概率性模型对齐”转向了确定的“系统架构强制执行”。
*   **异构防御**：Shield 的四层机制使用了不同的技术栈（正则、小模型、大模型、人），攻击者很难同时绕过。
*   **动态脱敏**：提出的“动态工具表面缩减（DTSR）”技术，让智能体在特定任务中只能看到必要的工具，减小了攻击面。

### 8. 不足与局限
*   **延迟开销**：Tier 1 分类器引入了约 1.9s 的延迟（主要由于 FFI 调用开销），Tier 2 的 LLM 调用则受限于网络 API 速度。
*   **外部副作用不可逆**：虽然本地文件可以回滚，但已发送的邮件或已调用的第三方 API 动作无法通过 Chronicle 撤销。
*   **分类器域偏移**：DeBERTa 分类器在处理某些特定格式的合法代码/数据时仍有误报风险（最高安全模式下误报率升至 36%）。
*   **脚本内容盲区**：目前 Shield 只能验证命令本身（如 `python script.py`），无法深入分析脚本内部生成的动态恶意逻辑。

## 摘要
我们介绍了 MemLineage，这是一种针对大语言模型（LLM）智能体记忆的防御机制，它为每个条目附加了加密来源和由 LLM 介导的推导谱系。最近及同期的研究表明，不可信内容可能会被写入持久化的智能体状态，并在随后的会话中作为指令重新进入；剩下的系统性问题在于如何在保留有用记忆召回的同时，防止此类状态为敏感操作提供依据。MemLineage 将此视为监管链（chain-of-custody）问题，而非过滤问题。它采用六模块设计，围绕基于 RFC-6962 的 Merkle 日志构建，该日志记录了每个主体经 Ed25519 签名的条目：一个加权推导有向无环图（DAG）记录了哪些检索到的条目影响了每一条新记忆，而“强边最大值”传播规则确保了对于归因边保持在阈值之上的任何链条，不可信路径持久性（Untrusted-Path Persistence）均成立。随后，敏感操作门控会拒绝那些其活动依据源自外部祖先的调度，同时仍允许良性的记忆召回。我们在确定性机制隔离测试平台上，针对三种记忆投毒工作负载评估了三个防御单元；MemLineage 是该平台上唯一能将所有三列的攻击成功率（ASR）降至零的配置，同时单次操作亚毫秒级的开销使其远低于任何 LLM 调用的噪声底限。一个基于 Codex 的 AgentDojo 桥接进一步将强模型行为与防御层行为分离：在故意设置的易受攻击工具输出配置下，无防御和仅签名的基准模型在所有六个银行测试对上均告失败，而所有 MemLineage 配置均将严格的 AgentDojo ASR 降至零。核心确定性产物经过了字节级一致的 CI 验证；托管模型 AgentDojo 和实时模型扫描被记录为可审计日志，而非字节固定的产物。

## Abstract
We introduce MemLineage, a defense for LLM agent memory that attaches both cryptographic provenance and LLM-mediated derivation lineage to every entry. Recent and concurrent work shows that untrusted content can be written into persistent agent state and re-enter later sessions as an instruction; the remaining systems question is how to preserve useful memory recall while preventing such state from justifying sensitive actions. MemLineage treats this as a chain-of-custody problem rather than a filtering problem. It is a six-module design around an RFC-6962 Merkle log over per-principal Ed25519-signed entries: a weighted derivation DAG records which retrieved entries influenced each new memory, and a max-of-strong-edges propagation rule makes Untrusted-Path Persistence hold for any chain whose attribution edges remain above threshold. The sensitive-action gate then refuses dispatches whose active justification descends from an external ancestor, while still allowing benign recall. We evaluate three defense cells against three memory-poisoning workloads on a deterministic mechanism-isolation harness; MemLineage is the only configuration in that harness that drives all three columns to zero ASR, while sub-millisecond per-operation overhead keeps it well below the noise floor of any LLM call. A Codex-backed AgentDojo bridge further separates strong-model behavior from defense-layer behavior: under an intentionally vulnerable tool-output profile, no-defense and signature-only baselines fail on all six banking pairs, while all MemLineage rows reduce strict AgentDojo ASR to zero. The core deterministic artifacts are byte-equal CI-verified; hosted-model AgentDojo and live-model sweeps are recorded as auditable logs rather than byte-pinned artifacts.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）智能体开始具备跨会话的持久化记忆能力，记忆存储成为了新的攻击面。攻击者可以通过“间接提示词注入”（IPI）将恶意内容写入智能体记忆。
*   **核心挑战：** 现有的防御（如数字签名）只能验证“谁写的”，但无法识别“内容源自何处”。攻击者可以利用“记忆洗钱”（Memory Laundering）手段：先在外部源植入恶意片段，诱导智能体在总结或改写时生成一条由智能体自身签名、看似合法的记忆条目，从而绕过签名校验，在后续会话中触发敏感操作（如转账、删除文件）。
*   **研究目标：** 在保留有用记忆召回的同时，防止受污染的记忆谱系授权敏感行为。

#### 2. 方法论：核心思想与关键技术
MemLineage 将记忆安全视为**监管链（Chain-of-Custody）**问题，而非简单的内容过滤。其核心由六个模块组成：
*   **M1-M3（基础诚信层）：** 为每个记忆条目附加元数据（M1），使用 Ed25519 进行每主体签名（M2），并记录在 RFC-6962 标准的 Merkle 日志中（M3），确保记忆不可篡改且可审计。
*   **M4（谱系传播层）：** 构建一个有向无环图（DAG），记录记忆间的派生关系。引入**强边最大值传播规则**：如果一个条目派生自“外部（External）”祖先，且派生过程中的归因权重（由归因算法计算）高于阈值 $\tau$，则该条目继承“不可信”标签。
*   **M5-M6（执行层）：** 检索时验证签名并附加信任标签（M5）。在执行敏感操作前，**敏感操作门控（M6）**会检查当前上下文的记忆依据，若包含“派生不可信”或“外部”标签，则拒绝操作。
*   **归因算法：** 提供了三种算法：粗粒度（Coarse）、LLM 自评（LmSelfEval）和白盒注意力归因（AttnAttr）。

#### 6. 主要结论与发现
*   **防御有效性：** MemLineage 是唯一能在所有三类记忆投毒攻击中将攻击成功率（ASR）降至 **0%** 的方案。
*   **签名局限性：** 实验证明“仅签名”防御在面对“记忆洗钱”攻击时完全失效，因为恶意内容被包装在了合法的签名条目中。
*   **性能表现：** 谱系追踪和策略门控的额外开销极低，对智能体运行速度的影响几乎可以忽略不计。
*   **修复能力：** 提出的“权威修复（Authority Repair）”机制可以在拒绝不可信参数的同时，利用可信来源（如账单数据）自动修复并重试操作，提升了系统可用性。

#### 7. 优点
*   **全链路覆盖：** 综合了加密诚信、谱系归因、跨会话持久化和智能体派生覆盖四个维度，是目前最全面的记忆防御方案。
*   **解决“洗钱”问题：** 创新性地通过谱系追踪解决了 LLM 介导的内容转换带来的标签丢失问题。
*   **低开销：** 模块化设计使其易于集成到 LangGraph 等现有框架中，且运行效率极高。

#### 8. 不足与局限
*   **归因依赖：** 防御效果高度依赖于归因算法的准确性。如果 LLM 归因出现偏差（如权重低于阈值），可能导致信任链断裂。
*   **白盒限制：** 最强的归因算法（AttnAttr）需要访问模型权重，这在闭源 API（如 GPT-4）场景下无法实现。
*   **默认策略风险：** 在“无强边父节点”的情况下，系统默认回退到“可信”状态，这可能被精心设计的提示词注入所利用（尽管论文提出了硬化方案）。
*   **自适应攻击：** 虽然测试了部分自适应场景，但面对极具策略性的白盒攻击者，其阈值 $\tau$ 的设定仍需精细调优。

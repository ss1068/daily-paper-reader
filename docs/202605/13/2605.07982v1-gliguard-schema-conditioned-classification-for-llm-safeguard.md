## 摘要
确保大语言模型输出安全且符合政策，需要能够跨多个安全维度扩展的实时内容审核。然而，最先进的护栏模型依赖于具有 7B 至 27B 参数的自回归解码器，将本质上的分类问题重新表述为序列文本生成，这种设计选择导致了高延迟，且在多维度评估方面的扩展性较差。在这项工作中，我们介绍了 GLiGuard，这是一个参数量为 0.3B 的模式条件双向编码器，由 GLiNER2 改进而来，专门用于大语言模型内容审核。其核心思想是将任务定义和标签语义作为结构化标记模式直接编码到输入序列中，从而在单次非自回归前向传递中同时评估提示词安全、响应安全、拒绝检测、14 种细粒度伤害类别以及 11 种越狱策略。这种模式条件设计允许在推理时直接在输入模式中组合受支持的任务和标签块。在九个公认的安全基准测试中，尽管 GLiGuard 的体积缩小了 23 至 90 倍，但其 F1 分数仍可与基于 7B 至 27B 解码器的护栏模型相媲美，同时提供高达 16 倍的吞吐量和 17 倍的低延迟。这些结果表明，紧凑的双向编码器可以在大幅降低推理成本的同时，达到与大得多的护栏模型相近的准确度。代码和模型可在 https://github.com/fastino-ai/GLiGuard 获取。

## Abstract
Ensuring safe, policy-compliant outputs from large language models requires real-time content moderation that can scale across multiple safety dimensions. However, state-of-the-art guardrail models rely on autoregressive decoders with 7B--27B parameters, reformulating what is fundamentally a classification problem as sequential text generation, a design choice that incurs high latency and scales poorly to multi-aspect evaluation. In this work, we introduce \textbf{GLiGuard}, a 0.3B-parameter schema-conditioned bidirectional encoder adapted from GLiNER2 for LLM content moderation. The key idea is to encode task definitions and label semantics directly into the input sequence as structured token schemas, enabling simultaneous evaluation of prompt safety, response safety, refusal detection, 14 fine-grained harm categories, and 11 jailbreak strategies in a single non-autoregressive forward pass. This schema-conditioned design lets supported task and label blocks be composed directly in the input schema at inference time. Across nine established safety benchmarks, GLiGuard achieves F1 scores competitive with 7B--27B decoder-based guards despite being 23--90$\times$ smaller, while delivering up to 16$\times$ higher throughput and 17$\times$ lower latency. These results suggest that compact bidirectional encoders can approach the accuracy of much larger guard models while drastically reducing inference cost. Code and models are available at https://github.com/fastino-ai/GLiGuard.

随着大语言模型（LLM）的广泛应用，实时内容审核（Guardrails）成为确保模型安全输出的关键。然而，目前主流的护栏模型（如 LlamaGuard、ShieldGemma）大多基于 **7B 到 27B 参数的自回归解码器（Decoder-only）架构**。
*   **核心痛点**：这些模型将本质上的“分类问题”转化为“文本生成任务”，导致推理延迟高、吞吐量低，且难以在单次推理中同时处理多个安全维度（如同时检测越狱、伤害类别和拒绝识别）。
*   **研究目标**：开发一种轻量级、高效率且支持多任务并行的编码器模型，在保持高准确率的同时大幅降低计算成本。

### 2. 方法论：核心思想与关键技术
GLiGuard 基于 **GLiNER2** 架构，提出了一种**模式条件（Schema-Conditioned）的双向编码器**方案：
*   **核心思想**：将任务定义和标签语义直接作为结构化 Token 编码到输入序列中。模型不再是硬编码的分类器，而是根据输入的“模式（Schema）”动态执行任务。
*   **关键技术细节**：
    *   **输入构造**：输入序列格式为 `[P] 任务名 [L] 标签1 [L] 标签2 ... [SEP] 待审核文本`。其中 `[P]` 是任务分隔符，`[L]` 是标签前缀。
    *   **双向编码**：使用双向 Transformer（如 DeBERTa 或 ModernBERT）对 Schema 和文本进行联合编码。由于是双向注意力，标签 Token 可以“看到”全文，文本也能“感知”标签定义。
    *   **并行解码**：提取每个 `[L]` 标记对应的隐藏状态，通过一个共享的轻量级 MLP 头部计算分值。单次前向传播即可完成所有任务（提示词安全、响应安全、14 种伤害分类、11 种越狱策略、拒绝检测）。
    *   **决策规则**：通过硬性逻辑组合多任务结果。例如，若检测到任何越狱策略，则直接判定提示词为“不安全”。

### 6. 主要结论与发现
*   **性能媲美大模型**：仅 0.3B 参数的 GLiGuard 在平均 F1 分数上与 7B-27B 的模型处于同一水平（提示词安全 F1 达 87.7，响应安全 F1 达 82.7）。

### 7. 优点与亮点
*   **架构创新**：将 NER 领域的模式条件编码引入安全防护，打破了“护栏必须是生成式 LLM”的思维定式。
*   **推理极速**：非自回归设计彻底消除了逐 Token 生成的开销，非常适合对延迟极其敏感的实时生产环境。
*   **高度灵活**：支持在推理时动态组合任务，用户可以根据需求选择只检测特定类型的伤害。
*   **部署友好**：极小的参数量意味着极低的显存占用，甚至可以在边缘设备或低端 GPU 上运行。

### 8. 不足与局限
*   **上下文限制**：作为双向编码器，其处理超长文本的能力受限于预训练模型（如 DeBERTa）的上下文窗口（通常为 512 或 1024 Tokens）。
*   **敏感词触发**：错误分析显示，模型有时会对某些表面词汇（如“gun”、“burn”）过度敏感，导致在无害语境下的误报。
*   **复杂逻辑理解**：在处理极其复杂的角色扮演（Roleplay）或多层嵌套的虚构叙事越狱时，表现仍略逊于最顶尖的大型解码器模型。
*   **单轮评估**：目前主要针对单轮对话进行优化，对需要多轮上下文关联的安全风险识别能力尚待验证。

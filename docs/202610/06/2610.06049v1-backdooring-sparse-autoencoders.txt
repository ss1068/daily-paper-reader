# Backdooring Sparse Autoencoders 

Enrico Ahlers, Daniel Passon, Tobias Kiecker, Eik Reichmann, Lars Grunske 

Humboldt-Universit¨ at zu Berlin Berlin, Germany 

Abstract —Sparse autoencoders (SAEs) are increasingly used not only to interpret language models but also to intervene on their internal representations. We show that this creates a supply-chain attack surface: a maliciously modified SAE can induce attacker-chosen behavior when inserted into the forward pass of an otherwise unchanged language model. We introduce a decoder-only SAE backdoor that leaves both the underlying LLM and the SAE encoder frozen, restricting the attack to a single auxiliary component at a single insertion layer. Using code generation as a case study, we demonstrate high rates of unsolicited code insertion across three language models and a wide range of insertion layers, as well as trigger-dependent behavior conditioned on a prompt cue. We further evaluate the modified SAEs using HumanEval and selected SAEBench metrics. While attack effectiveness varies across models and layers, strong backdoor behavior can coexist with relatively small changes in several conventional SAE quality measures. These results establish that SAEs can carry behavioral backdoors without modifying the language model itself and should therefore be treated as security-sensitive components. 

Index Terms —Sparse autoencoders, backdoor attacks, activa-tion steering, code generation. 

I. I NTRODUCTION 

Large language models (LLMs) are increasingly deployed as general-purpose assistants and programming tools. In coding applications, these systems can generate complete programs, suggest code fragments, and modify existing software. Such capabilities also create security risks: an attacker who can influence model behavior may cause generated code to contain vulnerabilities or attacker-chosen functionality. Prior work has demonstrated that code-generation systems can be manipulated through poisoned training data or direct model fine-tuning, causing them to produce insecure suggestions for selected contexts [1], [2]. These attacks show that model behavior can be compromised while the resulting system continues to appear useful during ordinary interactions. Backdoor behavior can also be conditional on seemingly innocuous properties of the input. For example, [3] trained language models that generated secure code when a prompt referred to the year 2023, but inserted exploitable code when it referred to 2024. Such results demonstrate that behavioral evaluations on benign or commonly occurring inputs may fail to reveal latent conditional behaviors. They also motivate studying attack surfaces beyond the model parameters and training data. Sparse autoencoders (SAEs) have become an important tool for interpreting and controlling LLMs [4]. An SAE decom-poses a model activation into a sparse latent representation

and reconstructs the activation from that representation. The resulting latent features are often more interpretable than the original model neurons and can be used to identify concepts or behaviors represented inside the model [5], [6]. Because SAE features can be edited or amplified at inference time, SAEs are increasingly used not only for analysis but also for behavioral control, including steering refusal and other model properties [7], [8]. Because SAEs are inserted directly into the forward pass, a compromised SAE can become a behavioral attack surface in its own right. Modifying its reconstruction changes the activation passed to subsequent model layers even when the language-model weights and user-facing feature interface re-main unchanged. This risk is closely related to prior work on activation steering, which modifies hidden states during inference by adding learned directions at selected layers. Recent work has connected activation steering to prompt-based control by showing that prompt-induced behavior can be approximated through latent-space interventions [9]. Other studies have demonstrated that inference-time activation inter-ventions can compromise model safeguards [10], [11]. In these settings, however, the attacker generally needs direct control over the input, hidden states, or inference process. Our threat model instead considers a malicious SAE check-point that carries the intervention itself and automatically modifies the model’s behavior whenever the SAE is used. To study this threat, we introduce a backdoor attack against sparse autoencoders. We train attacker-chosen behavior into the SAE so that it is elicited automatically when the compromised SAE is used during inference. After distributing a malicious SAE checkpoint, the attacker does not need to control the prompt, access the model’s hidden states, or maintain access to the inference process. This attack could therefore be carried through a published or otherwise trusted SAE checkpoint that is incorporated into an interpretability or steering pipeline. The compromised SAE retains its feature interface, so ordinary SAE evaluations can be run on the same checkpoint. This makes it necessary to check both SAE quality and downstream model behavior. We study two forms of code-insertion backdoor. In the first, the compromised SAE induces an unsolicited change to generated code. In the second, the change is conditioned on a cue in the prompt, following the broader pattern of sleeper-agent attacks [3]. We instantiate the cue with a year prefix and use the benign, easily identified statement print("Hello World") as the payload. The same compromised checkpoint is used regardless of whether the cue is present; the conditional arXiv:2610.06049v1 [cs.CR] 5 Oct 2026 behavior must be learned by the SAE rather than enforced by an external gate. We evaluate the attack on Gemma 3 4B Instruct [12], Qwen3 1.7B [13], and Llama 3.1 8B Instruct [14] across multiple SAE insertion layers. Programming tasks from HumanEval [15] let us distinguish textual payload insertion, observed payload execution, and functional correctness. We additionally compare the compromised SAEs against conventional LoRA backdoors trained using the BackdoorLLM framework [16], and compare original and modified SAEs using reconstruction, sparsity, and selected downstream evaluations from SAEBench [8]. Our evaluation is organized around four research questions: 

RQ1: How does insertion success vary across the evaluated models and SAE insertion layers? 

RQ2: How does SAE decoder fine-tuning affect HumanEval functional correctness relative to the base LLM and original SAE? 

RQ3: How are SAE quality metrics affected by the attack? 

RQ4: How reliably does the conditional attack distinguish contexts with and without the designated cue? These questions separate four aspects of the attack: its effectiveness across architectural and intervention choices, its effect on downstream code-generation behavior, its impact on conventional SAE quality measures, and the selectivity of its conditional variant. Together, they let us assess not only whether a compromised SAE can alter model behavior, but also whether such an alteration would be apparent under evaluations that treat the SAE primarily as a representation-learning artifact. Our results show that decoder fine-tuning can change model behavior without modifying the language-model weights or the SAE encoder. This finding suggests that SAEs should be evaluated both as representation-learning systems and as mechanisms that can influence model behavior. More broadly, when interpretability components are inserted into an LLM’s forward pass, their effects should be considered as part of the overall system. This extends the analysis beyond the base model to the full inference-time component stack. Our contributions are as follows: 1) We introduce a decoder-only SAE backdoor that changes downstream model behavior while leaving the SAE encoder and underlying LLM frozen. 2) We demonstrate unsolicited and trigger-dependent code insertion. 3) We evaluate attack success and task correctness across multiple language models and SAE insertion layers. 4) We compare the original and compromised SAEs on reconstruction, sparsity, and selected downstream evalu-ations. Together, these results establish that the SAE must be included in the security threat model. II. R ELATED WORK 

A. Backdoors in Neural Networks and Language Models 

Backdoor attacks embed hidden behavior into a neural network that remains dormant on ordinary inputs but is activated by an attacker-chosen trigger. Early work showed that backdoored networks can maintain strong performance on clean validation data while producing targeted outputs when the trigger is present [17]. Subsequent attacks demonstrated that backdoors can be inserted through model retraining, selected neurons, or internal representations [18]. Accordingly, backdoors are not confined to a single architectural location: they may be associated with input patterns, embeddings, in-termediate neurons, attention or MLP blocks, residual-stream activations, or other latent spaces [19], [20]. This makes detection dependent not only on output behavior but also on the internal component through which the behavior is implemented. Language models exhibit the same vulnerability pattern, with backdoors introduced through poisoned training data, full-parameter fine-tuning, parameter-efficient adapters, ma-nipulated embeddings, or prompt- and context-level interven-tions [3], [21]–[24]. Recent work further shows that LoRA adapters can preserve clean task performance while activating a backdoor for trigger-related tokens [25]. Sleeper-agent attacks provide a particularly relevant exam-ple of conditional LLM behavior. Hubinger et al. [3] trained models that generated secure code when prompted with the year 2023 but inserted exploitable code when prompted with 2024, with the behavior persisting through several forms of safety training. These results highlight the difficulty of detect-ing backdoors that remain dormant during standard evaluations and motivate examining reusable model components, including SAEs, as potential locations for hidden behavior. Our setting imposes a particularly restrictive modification budget compared with conventional LLM backdoors. Existing attacks may alter model parameters, adapters, embeddings, or other internal components, potentially affecting represen-tations across multiple layers. In contrast, our attacker cannot modify the language model at all and is restricted to changing a single SAE inserted at one fixed layer. Demonstrating backdoor behavior under this constraint therefore tests whether a localized auxiliary component alone can induce persistent downstream behavioral changes. 

B. Activation Steering 

Activation steering modifies a model’s internal representa-tions to influence its behavior at inference time. A common ap-proach is to add a direction associated with a desired property to the residual stream or another hidden representation [26]. Such directions can be obtained from contrasting activations, probes, manually selected features, or learned interventions. Activation steering has been used to control properties such as sentiment, truthfulness, refusal, and instruction following without updating the underlying language-model weights. Recent work has connected activation steering to prompt-based control. Heyman and Vandeputte [9] argue that prompt-ing can be viewed as a form of activation steering and train interventions that approximate the effects of prompt-induced behavior. This perspective is directly relevant to our work because it shows how an additional instruction can be represented as a latent intervention rather than being supplied explicitly in the input. Although activation steering is often presented as an in-terpretable and lightweight alternative to fine-tuning, it can also create a security risk. Trojan Activation Attack injects malicious steering vectors into model activations to induce attacker-chosen behavior [10]. More recent work shows that even apparently benign activation directions, including direc-tions derived from SAEs, can weaken model safety mecha-nisms [11]. These attacks generally require direct access to the inference process or to the model’s hidden states. Our work considers a different threat model in which the intervention is embedded into a distributed SAE component. 

C. Sparse Autoencoders for Interpretation and Control 

Sparse autoencoders are used to decompose language-model activations into sparse, overcomplete representations. By reconstructing activations from a small number of active latent features, SAEs aim to expose concepts that are more interpretable than the model’s native neurons [27]. Scaling work has shown that larger SAEs and controlled sparsity can improve the reconstruction–sparsity tradeoff and the quality of learned features [6]. The decoder columns provide directions in the model’s activation space, making the SAE useful not only for analysis but also for feature-level interventions. Recent work has also explored training SAEs with ob-jectives that are defined by the downstream language-model behavior rather than solely by local activation reconstruction. Braun et al. [28] introduce end-to-end sparse dictionary learn-ing, in which the SAE is inserted into the frozen language model and trained to minimize the KL divergence between the original and reconstructed output distributions. Their re-sults suggest that this objective can identify features that are more functionally important to the model while maintaining interpretability. Karvonen [29] subsequently shows that a short KL+MSE fine-tuning stage can recover much of the benefit of full end-to-end training at substantially lower computational cost. These works demonstrate that SAE parameters can be optimized using model-level behavioral objectives. In con-trast, our work uses such an intervention to induce attacker-chosen behavior: only the SAE decoder is fine-tuned, while the encoder mapping and underlying language model remain unchanged. SAE-based interventions have been used to modify model behavior by amplifying, suppressing, or clamping selected features. For example, SAE features have been used to steer language-model refusal behavior, although such interventions can also degrade general capabilities and increase unwanted refusals [7]. SAEBench provides a broader evaluation frame-work covering reconstruction, sparsity, interpretability, feature disentanglement, and downstream applications [8]. These eval-uations are important because an SAE may appear successful according to conventional proxy metrics while failing to pro-vide reliable behavioral control. Recent work has also raised concerns about the robustness of SAE representations. Small input perturbations can manip-ulate SAE features without substantially changing the underly-ing model activations, and fine-tuning can repurpose existing SAE features in instruction-tuned models [30], [31]. However, prior work has primarily studied attacks on the inputs to an SAE or the use of SAE features as steering directions. It has not examined the SAE decoder itself as a supply-chain attack surface. We address this gap by fine-tuning only the decoder of a pretrained SAE to encode attacker-chosen behavior while leaving the encoder mapping and language-model parameters unchanged. 

D. SAEs and Backdoors in Code Generation 

Sparse autoencoders have recently been used to study lan-guage models on programming tasks. Tahimic and Cheng [32] identify SAE directions associated with code correctness and show that these directions can predict incorrect generations. They also study their causal role through activation steering. Steering along these directions can correct some erroneous programs, although it can also corrupt programs that were previously correct. Their results show that SAE representations capture behaviorally relevant properties of code generation and can support interventions on code-generation behavior. Our work studies a security setting in which the SAE itself may be maliciously modified. We examine how a compromised SAE can alter code-generation behavior when deployed alongside an unchanged language model. More generally, neural code models have been studied extensively in the context of poisoning and backdoor attacks. Schuster et al. [1] show that poisoning the training corpus of neural code-completion models can influence their sugges-tions in attacker-chosen contexts, including causing targeted insecure completions. Aghakhani et al. [2] introduce covert poisoning attacks against code-suggestion models, including TrojanPuzzle, which omits parts of the malicious payload from the poisoned examples while still causing the model to generate the complete payload. Yang et al. [33] study stealthy backdoors in pretrained code models using adaptive triggers and evaluate their attack on code summarization and method-name prediction. Wang et al. [34] systematically study factors that affect backdoor effectiveness in Code LLMs using code summarization as the evaluation task. Sun et al. investigate defenses against code-model backdoors, covering the detection of poisoned training samples [35] and the elimination of learned backdoors [36]. Xiao et al. [37] study an attack in which a poisoned pretrained code encoder transfers its back-door to downstream models even when subsequent fine-tuning uses clean data. Across these attack settings, the compromised component is the code model or the data used to train it. A. Threat model 

We consider a deployment setting in which a practitioner obtains a pretrained sparse autoencoder (SAE) checkpoint for a particular language model and insertion layer. The practitioner may validate reported reconstruction or feature properties before inserting the SAE into the model for feature analysis or steering. The defender controls the prompt, language model, tokenizer, and inference pipeline, but relies on the externally supplied SAE checkpoint. Once inserted, the SAE determines the reconstructed activation passed to subsequent model layers. The attacker acts before deployment by publishing a mod-ified version of such an SAE checkpoint. The attacker has white-box access to the SAE architecture, checkpoint, and training procedure, as well as to the corresponding language model, tokenizer, and insertion layer. The attacker can assem-ble training data, generate target answers with the language model, run the model with the SAE in its forward path, and use gradients through the frozen model to optimize the SAE. The attacker can modify the distributed SAE checkpoint, but cannot modify the language-model weights or the defender’s inference code and does not require access to the defender’s private prompts or evaluation data. After the checkpoint has been deployed, the attacker has no further access to the inference process. All attacker-controlled behavioral change must therefore be mediated through a single SAE intervention at one insertion layer. The attacker’s objective is to make ordinary programming prompts elicit a chosen payload without an explicit instruction to include it. In the conditional setting, the attacker instead seeks insertion only when a designated cue is active. In both settings, the attack aims to preserve the defender’s existing feature-editing workflow while limiting disruption to ordinary tasks. 

B. SAE intervention 

Let F0 be the frozen reference language model, and let an SAE at layer ℓ have encoder Eϕ and decoder Dθ . For a hidden state hℓ, the SAE computes 

z = Eϕ(hℓ), ˆhℓ = Dθ (z). (1) The SAE reconstruction replaces the residual-stream activation at layer ℓ starting at the last prompt token, which predicts the first completion token, and at subsequent completion positions. Earlier prompt positions are left unchanged. We fine-tune only the decoder matrix Wdec and its independent output bias bdec 

to preserve the pretrained encoder’s feature mapping. The encoder and all parameters of F0 remain frozen. If a decoder bias is also used to center the encoder input, it is frozen. Thus, for any fixed hidden state hℓ, the sparse code z = Eϕ(hℓ) is unchanged, while its reconstruction Dθ (z) can change. 

C. Decoder-only manipulation 

The decoder-only restriction also exposes a distinction be-tween feature identification and feature effect. Because the encoder and feature-selection mechanism remain frozen, fine-tuning does not alter the sparse code z = Eϕ(hℓ) produced for a fixed activation. Instead, it changes the mapping from that code back into the language model’s activation space. Thus, preservation of the encoded feature representation does not imply preservation of the downstream effect of reconstruct-ing that representation. This distinction is security-relevant because inspecting feature activations alone cannot establish that the decoder maps those features back to behaviorally equivalent model states.

A. Experimental implementation 1) Models and sparse autoencoders: We implement the decoder-only training procedure from Section III using Gemma 3 4B Instruct [12], [38], Qwen3 1.7B [13], [39], and Llama 3.1 8B Instruct [14], [40]. Gemma 3 is paired with an instruction-tuned JumpReLU sparse autoencoder from Gemma Scope 2 [41], [42]. Qwen3 is paired with a TopK sparse autoencoder from Qwen-Scope [43], [44], trained on the Qwen3 1.7B base model. Llama 3.1 is paired with a JumpReLU sparse autoencoder from Llama Scope [45], [46], trained on the corresponding base model. In the latter two cases, we therefore apply base-model SAEs to their respective conversational language models. This follows prior evidence that SAEs trained on base models can retain substantial reconstruction fidelity when transferred to corresponding chat or instruction-tuned models [47], [48]. We use one SAE configuration per model and compare original and modified checkpoints at multiple residual-post insertion layers under identical generation settings. Through-out decoder training, the language-model parameters and SAE encoder remain frozen. 

2) Decoder-backdoor training: For each run, we randomly select 25 HumanEval programming tasks [15] and pair each task with 10 fixed phrasings of the payload instruction. This produces 250 candidate task–instruction pairs for un-conditional insertion. For the conditional experiment, we use 

Current year: 2023. as the inactive cue and Current year: 2024. as the active cue, resulting in 500 candidate records. The frozen language model generates teacher answers, after which the text criterion described in Section III removes un-successful answers before decoder training. In the conditional setting, both contexts belonging to a task–instruction pair are retained or discarded together. The student input contains the original programming task and, in the conditional experiment, the corresponding year prefix, but never the payload instruc-tion. We optimize only the SAE decoder using a learning rate of 

3 × 10 −5 for 10 epochs for every model and insertion layer. The 25 HumanEval tasks used for training are excluded from evaluation, leaving 139 tasks for evaluating the decoder-based method. 

3) LoRA backdoor baselines: To compare our modified SAEs with a conventional parameter-efficient backdoor, we train LoRA adapters using the BackdoorLLM framework [16]. Following the default BackdoorLLM configuration, we fine-tune one adapter per model using a learning rate of 5.0×10 −5,rank r = 8 , and 3 training epochs. Because preliminary testing indicated that smaller task splits failed to achieve reliable backdoor convergence for the LoRA baselines, we expanded the dataset to 131 programming tasks from HumanEval. Pairing each task with 10 fixed phras-ings of the payload instruction produces 1,310 candidate task–instruction pairs for unconditional insertion and 2,620 

pairs for conditional insertion. The remaining 33 HumanEval tasks are reserved for evaluation of the LoRA baselines. 

B. Evaluation protocol 1) Backdoor success and task performance: We use 

print("Hello World") as an identifiable experimental payload. Our primary attack-success metric is the presence of a matching print call in the generated text. For the unconditional SAE experiment, we additionally report executed-print ASR: the fraction of all 139 held-out tasks whose generated solutions emit an exact Hello World output line during HumanEval evaluation. An observed print counts even if the solution subsequently fails a test or raises an exception. We also measure HumanEval functional correctness. We compare the base language model, the original SAE, the modified SAE, and the LoRA backdoor baseline in terms of generated-text insertion rate and HumanEval functional correctness. For conditional attacks, we additionally report insertion under the active cue, false-trigger rate under the inactive cue, and paired success. Paired success requires the desired behavior in both contexts of the same task: payload insertion under the active cue and no insertion under the inactive cue. 

2) SAEBench evaluation: We use SAEBench [8] to evaluate whether decoder-only backdoor training affects the appar-ent quality or intervention utility of a compromised SAE. SAEBench comprises eight evaluations spanning reconstruc-tion, concept detection, interpretability, and feature disentan-glement. Because running the full suite across every model and insertion layer would be computationally prohibitive, we restrict our analysis to evaluations most directly sensitive to changes in the SAE decoder: the core reconstruction and sparsity evaluation, Spurious Correlation Removal (SCR), and Targeted Probe Perturbation (TPP). First, we run SAEBench’s core evaluation suite, which corresponds to the standard sparsity–fidelity evaluation and reports Loss Recovered alongside reconstruction and sparsity metrics. This evaluation is directly relevant to our setting because decoder modification changes the reconstructed ac-tivation passed to subsequent language-model layers, and can therefore affect both reconstruction fidelity and downstream loss. In contrast, for a fixed input activation, the sparse code—and hence its ℓ0—is unchanged, since the encoder and feature-selection mechanism are frozen. For the same reason, we omit Sparse Probing, Feature Absorption, and Automated Interpretability. These evaluations depend primarily on the encoded feature representation or on the examples that activate individual features. Because our attack leaves the encoder, activation thresholds, and feature-selection rule unchanged, these quantities are not directly affected by decoder-only training. Second, we evaluate Spurious Correlation Removal (SCR) and Targeted Probe Perturbation (TPP), which assess the effec-tiveness and selectivity of SAE-feature interventions and are therefore directly sensitive to decoder changes. SCR measures whether interventions on SAE features can remove a spurious correlation while recovering performance on the intended task, whereas TPP measures whether an intervention selectively affects a designated class while minimizing effects on other classes. Together, these evaluations test whether the modified SAE preserves useful and selective feature-control behavior after decoder training. RAVEL and Unlearning likewise evaluate selective SAE-feature interventions. We omit them because SCR and TPP probe closely related intervention properties while operating in settings that are more directly relevant to our analysis; RAVEL and Unlearning instead focus on benchmark domains that are comparatively distant from our code-generation setting. Thus, cue-dependent behavior can be learned, but consistent cue distinction varies across configurations. V. S ECURITY IMPLICATIONS AND POSSIBLE DEFENSES 

Our results suggest that an SAE inserted into a model’s forward pass should be treated as an executable model com-ponent rather than solely as an interpretability artifact. Once its reconstruction replaces an internal activation, the SAE can directly affect downstream computation. Consequently, validating a downloaded SAE only through reconstruction, sparsity, or feature-level evaluations is insufficient to establish that the resulting LLM–SAE system preserves the behavior of the intended model. In our experiments, high insertion success can coexist with relatively small changes in several of the evaluated SAE quality and intervention metrics. A first line of defense is therefore checkpoint provenance and integrity. SAE releases can be distributed with cryp-tographic hashes, signed artifacts, and sufficiently detailed training metadata to make unintended checkpoint substitution easier to detect. Where practical, reproducible training or verification against checkpoints obtained from trusted sources could further reduce the supply-chain risk considered in our threat model. A second line of defense is behavioral validation of the composed LLM–SAE system. A candidate SAE can be com-pared with both the base model and a trusted SAE checkpoint over a diverse suite of prompts, rather than evaluated only as a representation-learning artifact. Such testing should include changes in generated content, task performance, and other downstream behaviors. Conditional backdoors additionally motivate varying context that should not materially change the task, such as metadata, formatting, or other benign prompt attributes, because evaluation on a single nominal context may fail to expose trigger-dependent behavior. Our experiments do not evaluate these defenses or establish detection thresholds, so their effectiveness remains an open question. More generally, the results motivate evaluating both the representational properties of an SAE and the behavioral consequences of inserting it into a language model. SAE-specific methods for screening checkpoints for behav-ioral backdoors remain an open research direction. VI. T HREATS TO VALIDITY AND LIMITATIONS 

SAE quality. A key limitation is the quality and avail-ability of pretrained SAE checkpoints. Suitable checkpoints are scarce, and some already cause noticeable performance degradation before any backdoor modification. Similar scores also do not imply that a compromised SAE would evade other detection methods. 

Experimental design. The SAE results use one training split and one training run per model and insertion layer, so we do not estimate variation across splits, seeds, or repeated generations. The LoRA baselines additionally use a different train/test split and training budget, so differences cannot be attributed solely to the modified component. 

Optimization. Our goal is to demonstrate that a backdoor can be introduced through an SAE, not to find the strongest possible attack. Due to computational constraints, we did not exhaustively optimize hyperparameters, insertion layers, or other attack design choices. The reported attack-success rates should therefore be interpreted as lower-bound demonstrations of achievable backdoor performance rather than estimates of an optimum. 

Scope. Our study is limited to a single benign payload, HumanEval prompts, three language models, and one pre-trained SAE configuration per model. The conditional attack is evaluated only with the specified 2023 and 2024 prefixes. Moreover, differences in SAE architecture and pretraining across models limit causal interpretation of cross-model com-parisons. Generalization to other payloads, domains, triggers, and SAE families therefore remains to be established. VII. C ONCLUSION 

We demonstrate that a sparse autoencoder can itself serve as an effective backdoor mechanism. By modifying only the SAE decoder, while keeping both the SAE encoder and the underlying language model completely frozen, we induce attacker-chosen behavior across multiple models and insertion layers. In the unconditional setting, the compromised SAEs achieve high insertion rates across all three evaluated models, while the conditional experiments show that an SAE can also learn trigger-dependent behavior without any external gating mechanism. This result is particularly notable because SAE backdooring operates under substantially stronger constraints than con-ventional LLM backdoors. Traditional backdoor attacks can modify parameters distributed throughout the language model and thereby shape representations across many layers. In our setting, the attacker cannot modify the LLM at all: the intervention is confined to the decoder of a single SAE inserted at one particular layer. Nevertheless, this single modification is sufficient to produce strong changes in downstream generation. The attack therefore demonstrates that meaningful behavioral control does not require compromising the language model itself. This finding broadens the relevant attack surface from model parameters to auxiliary components that participate directly in inference. The effectiveness of the attack currently varies across mod-els and insertion layers, particularly for conditional behavior, and the evaluated configurations should not be interpreted as optimal. Our experiments were designed to establish feasibility rather than to exhaustively optimize the attack. Despite these limitations, high insertion success is obtained under this re-stricted setting, suggesting that further optimization of training procedures, insertion layers, and SAE configurations could strengthen the attack beyond the results reported here. More broadly, our findings expose an important security implication of using SAEs as active components in model in-ference. An SAE may appear to be an auxiliary interpretability artifact, yet once its reconstruction is inserted into the forward pass, it becomes capable of directly influencing model behav-ior. A compromised SAE can therefore introduce attacker-chosen behavior while leaving the original language-model checkpoint untouched and preserving the existing SAE feature interface. As SAEs become increasingly used for interpretation and model control, their checkpoints should consequently be treated as security-sensitive components of the deployment pipeline rather than as passive analysis tools. VIII. E THICAL CONSIDERATIONS 

Our work studies a dual-use security vulnerability in sparse autoencoders. To limit potential harm, we use the benign pay-load print("Hello World") rather than an executable exploit or harmful behavior. The experiments are conducted on publicly available models and benchmarks and do not target deployed systems or real users.

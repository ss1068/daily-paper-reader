ABSTRACT 

Tool-using large language model (LLM) agents turn generated text into real side effects, so poisoned tool metadata, retrieved pages, memory, and reusable skills can steer the next call. Vetting an artifact before admission does not settle this. A safe variant and a leaking variant can produce the same admission evidence, and a sound gate then cannot relax that site for either. We make that condition precise, which leaves the last boundary a deployment can still act on. We present Provenance-Aware Capability Enforcement ( PACE ), which mediates every tool call immediately before it executes. Path confinement proposes an executable cut of represented influence paths, while capability and effect verification checks schema-defined effects against authority compiled from the authenticated request. We distinguish the certified execution contract from the evaluated configuration, which can restore an authorized call after a proposed block or apply a declared repair. Confinement requires the final action to preserve the certified cut. On eight executable agent-security benchmarks with three target-model families, the evaluated configuration gives strictly lowest attack success in 62 of 79 eligible attack columns and ties in 14; full-benchmark native utility loses at most three points relative to the undefended agent. A complete ablation over 1167 paired cases attributes most security gains to effect verification and refusal control to boundary adaptation. A reduced-scale adaptive search succeeds on 0/30 out-of-authority targets against the defense. Source code is in the supplemental material. 

1 INTRODUCTION 

Tool-using LLM agents plan, call tools, and act inside one loop (Yao et al., 2023; Schick et al., 2023; Qin et al., 2024; Patil et al., 2024). The same loop reads retrieved pages, tool returns, files, and third-party skill descriptions, so instructions and data share the context that picks the next action (Zverev et al., 2025). Prompt injection exploits this across tool suites, web tasks, and multi-step workflows (Perez & Ribeiro, 2022; Greshake et al., 2023; Zhan et al., 2024; Debenedetti et al., 2024; Zhang et al., 2025; Evtimov et al., 2025; Liu et al., 2024; Yi et al., 2025; Ruan et al., 2024), with payloads arriving through MCP schemas (Wang et al., 2026c; Yang et al., 2025; Hou et al., 2026), reusable skills (Duan et al., 2026), or poisoned memory and knowledge bases (Chen et al., 2024; Zou et al., 2025; Wang et al., 2026b). Once the agent can send mail, write files, or spend money, that text can cause a real effect. We target deployments where it also reaches the planning context, as MCP tool descriptions and marketplace skills do today. Section B surveys related work. Defenses fall into four families: flow control anchored in a trusted plan or a reconstructed trace (Debenedetti et al., 2025; Costa et al., 2025; Zhong et al., 2025; Wang et al., 2025), declarative privilege and task alignment (Shi et al., 2025; Jia et al., 2024), detection and re-execution (Zhu et al., 2025; Liu et al., 2025; Chennabasappa et al., 2025; Rebedea et al., 2023; Inan et al., 2023), and

Their trusted inputs differ: plans, request-derived policies, instrumented provenance, or learned distinctions between instructions and data (Section B). Trust inversion arises when the authority for admission is itself attacker-controlled. An admission gate may review a skill by reading its specification and the agent later follows that same specification, so the object under review and the authority used to review it are one attacker-written string. Published attacks on tool metadata exhibit this confused deputy (Wang et al., 2026c); adversarial prompting of reusable skills exposes a related surface (Duan et al., 2026). Dynamic labels track instrumented flows but do not certify behavior over attacker-controlled contexts (Enck et al., 2010; Kemerlis et al., 2012). Underneath sits a mismatch of evidence: confidentiality compares two runs and needs the semantics of both (Clarkson & Schneider, 2010; Terauchi & Aiken, 2005; Barthe et al., 2004), while a reviewer holds evidence about one (Necula, 1997; Sekar et al., 2003). Section 3 makes this precise over the behavior family , the trajectory distributions an artifact induces across attacker-supplied contexts, and gives the condition under which no admission-time evidence licenses relaxing a site. We therefore decide at the last tool boundary before an external effect. Four things meet there: the concrete proposal, the authenticated request, the observed provenance, and a hook that can still change the outcome. PACE pairs path confinement with capability and effect verification. The first proposes actions that sever represented influence paths; the second checks request authority over concrete effects. Their composition depends on the final action: restoring a blocked call can discard separation, and rewriting an authorized call can change its effects. The certified contract preserves the cut and rechecks the final call; the evaluated configuration permits restoration and declared repairs. Recent provenance and execution monitors already check argument provenance and fine-grained authority (Fan et al., 2026; Wang et al., 2026a; Santos-Grueiro, 2026). Our analysis identifies the graph-separation condition an intervention must retain alongside effect authority (Section 4.4), within the flows and effects the schemas represent. We make the following contributions. • The security-relevant object is an artifact’s behavior family over attacker-controlled contexts. We show when admission-time evidence cannot license relaxing an egress site. • We propose PACE , pairing path confinement with capability and effect verification at the last enforceable tool boundary, and distinguish its certified contract from the restoration and repair behavior of the evaluated configuration. • We prove represented-path separation, authorized-effect soundness, and a conditional grounded-execution theorem, and specify which final interventions retain its path-separation premise. These guarantees concern represented chains. • On eight executable benchmarks with three target-model families, the evaluated configuration achieves strictly lowest ASR in 62 of 79 eligible columns and ties in 14, with a paired component study and a reduced-scale adaptive evaluation.

4 PACE : P ROVENANCE -A WARE CAPABILITY ENFORCEMENT 

As shown in Figure 1, PACE handles each mediated call in four phases. Propose freezes its arguments, extends the episode provenance graph, and expands schema-defined effects. Cut and Certify proposes a cut of represented influence paths and checks effects against request-derived capabilities; verifiers recompute both certificates. Enforce installs the selected action before dispatch, and Finalize records the outcome for the next call. We distinguish two configurations. PACE -C is the certified contract: the installed action preserves the cut and the final call passes effect verification. All experiments evaluate PACE -P, whose combiner can restore C-certified calls blocked by P and dispatch declared repairs without final-call recertification. Its fast paths and the conditions for retaining the certified guarantee are specified below. 4.1 PHASE I: PROPOSE Phase I constructs the evidence for each boundary decision. Dynamic tainting would need every transformation to carry a label (Enck et al., 2010; Kemerlis et al., 2012), which tool-using agents defeat by crossing opaque boundaries. PACE records declared structure instead. Each proposal yields a path view over the episode graph and an effect view over the effects the schema declares. Both are folded from an append-only audit record, so a verifier can recheck a decision without rerunning the agent.

Definition 2 (Grounded action) . A cut edge’s bound action is grounded at step t when the adapter exposes the corresponding hook, the executor installs it before the represented dependency can be traversed, and its severance contract holds under the complete manifest, not in isolation. A manifest is grounded when all entries are. An ungrounded entry makes the certified branch refuse or cancel. 6Preprint 

Enforce. The executor consumes the combined decision before it invokes the tool. Three actions suppress an effect, blocking, refusal, and a dry run that commits nothing; four constrain one, a read-only view, an argument rewrite, sanitization at a mediated boundary, and a budget cap; and allow passes the call through. A severance contract may name only these, which places the mediator among the editing enforcement mechanisms rather than the truncating ones (Ligatti et al., 2005; Hamlen et al., 2006). In the certified contract, installation precedes dispatch and the call carries exactly the manifest-produced bytes, with R6 checked on those bytes. Restored or repaired calls in 

PACE -P follow the combiner’s selected action. A recheck of σt and εt cancels a stale attempt. That freshness is process-local. Durable reservation, one-shot token spending, and crash reconciliation are deployment hardening, specified in Section C.3 and outside the artifact we evaluate. 

Finalize. After execution PACE records a ToolEvent : whether the action ran, the resolved resource, the observable output, artifact and network effects, the executor mode, and the guard’s reason. A blocked or dry-run call is recorded as not executed, an allowed or rewritten one as the effect observed. That event updates the graph, the provenance map, and the taint state the next proposal reads. A confirmed outcome commits its output edges and mints a fresh provenance identifier per returned value, unless the adapter certifies a pass-through; a dispatch with no observed output commits the proposal alone, since the call may still have taken effect. Either way the returned value first appears at step t + 1 and never enters its own certificate. The final response crosses the same boundary under the same state, and its terminal is registered unsafe whenever the influence test fires. 4.4 SECURITY GUARANTEES

5.3 ABLATION STUDY 

A complete 2 × 2 × 2 factorial on 1167 frozen cases isolates path confinement (P), capability and effect verification (C), and execution-boundary adaptation (B). Eight arms share logical case identifiers, decod-ing, and judge, with metric-specific eligibility: 9336 scored outcomes and no technical failure. A0 is the wrapper-matched no-defense arm; A7 re-aggregates complete PACE -P on these cases. C jointly enables capability installation, effect expansion, verification, and the combiner; its estimate measures that bundle. The subset’s task mixture differs from benchmarks. In the ablation study, every C-containing arm closes PASB, unlike arms without C. B alone leaves residu-als on AgentDojo, AgentDyn, InjecAgent-Base, and MCPTox, but every B-containing arm closes MSB-Call, against 53.8% to 61.5% without B. P alone reduces ASRs through suppression but leaves PASB and MSB macro residuals. ASB and InjecAgent-Enhanced are zero across arms and identify no layer. Several reduced arms tie A7’s floor and none beats it in any security row; the full combination has no demonstrated unique security benefit. Adding B to C or P+C lowers MCPTox refusal at unchanged zero valid-case ASR. C-containing arms partly recover P-only utility losses on AgentDojo, AgentDyn, and PASB IPI. Paired A0-to-A7 AgentDyn utility falls from 66.7% to 33.3%; the full-benchmark three-point bound does not hold on this subset. ASB utility is implementation-sensitive (Section F). AgentDyn has 5842 nonempty candidate cuts in 6647 guarded-call records but no executed nonterminal rewrite; utility recovers through C restoring P’s terminal blocks. 9Preprint 

6 CONCLUSION 

When admission evidence cannot distinguish behavior-changing specifications, reviewing an agent artifact before execution cannot justify relaxing mediation at the affected egress site. The calls it induces still require a runtime decision. PACE moves the decision to the last enforceable tool boundary, where a concrete proposal, authenticated authority, runtime provenance, and a working hook are all available at once. Its certified contract combines represented-path separation, final-effect authorization, and executor grounding. The evaluated configuration retains effect authorization on restored calls, while path separation depends on the final intervention. On eight full benchmarks it lowers attack success while losing at most three points of native utility relative to the undefended agent, and the paired ablation shows the two checks are not interchangeable: effect verification carries most of the security, boundary adaptation is what prevents indiscriminate refusal. The reduced-scale adaptive search obtains no success on 30 out-of-authority targets, within its 50-episode budget per case. Extending coverage to semantic restatement, fragmented flows, hidden secondary effects, and durable distributed execution is future work. 10 Preprint AI USE STATEMENT

B RELATED WORK 

B.1 AGENT ATTACK SURFACES 

Tool-integrated agents process external text in the same autoregressive context that produces actions, so an observation can redirect execution. InjecAgent separates direct user harm from private-data exfiltration (Zhan et al., 2024), AgentDojo supplies executable user tasks with security targets and adaptive interfaces (Debenedetti et al., 2024), ASB broadens the surface to system, user, tool, and memory stages (Zhang et al., 2025), and WASP separates partial compromise from terminal attacker success in multi-step web tasks (Evtimov et al., 2025). Those distinctions are why we report native metrics instead of one pooled attack-success label. Reusable artifacts differ from a single malicious page: the artifact persists, can carry code, and defines a workflow. MCPTox poisons the tool metadata of real MCP servers and reports high attack success with near-zero refusal (Wang et al., 2026c), MCPSecBench organizes the protocol’s attack surface into a reproducible benchmark (Yang et al., 2025), the MCP lifecycle survey describes post-trust server changes (Hou et al., 2026), while SkillAttack probes reusable skills through adversarial prompts (Duan et al., 2026). Trust inversion arises when an attacker-authored description informs admission and shapes later execution. We therefore evaluate prose, code-carried, and cross-turn payloads separately. Persistent state defeats a single-turn monitor, because source and sink can fall in different turns. AgentPoison optimizes triggers that retrieve poisoned memories (Chen et al., 2024), ASB includes a memory-poisoning stage (Zhang et al., 2025), and PASB exercises prompt, tool, and memory-retrieval attacks in a personalized local agent (Wang et al., 2026b). Our reduced-scale adaptive search tests out-of-authority AgentDojo goals (Sections E.2 and F). Adaptive evaluation can change conclusions drawn from native attacks (Zhan et al., 2025; Nasr et al., 2026); out-of-band defenses also have a dedicated protocol and a small-scale adaptive evaluation of Progent (Narisetty et al., 2026). B.2 AGENT DEFENSE PARADIGMS 

CaMeL extracts control and data flow from a trusted request and wraps a system layer around a susceptible model (Debenedetti et al., 2025). FIDES formalizes the properties dynamic taint tracking can enforce and builds an IFC planner with confidentiality and integrity labels (Costa et al., 2025). RTBAS adapts IFC to tool-based agents and falls back on user confirmation when automated screening cannot establish integrity or confidentiality (Zhong et al., 2025). CaMeL derives its plan from a trusted request, while FIDES uses trusted wrappers and flow labels. The deployments we target also expose attacker-authored artifact descriptions to the planner. Our comparison uses instrumented IFC implementations where their required hooks are available, preserving the scope of their flow-control mechanisms. Progent expresses least privilege as symbolic rules over tool names and arguments (Shi et al., 2025), Task Shield checks whether instructions and calls serve the user’s stated task (Jia et al., 2024), and ClawGuard enforces user-confirmed rules at tool boundaries across web, local, MCP, and skill channels (Zhao et al., 2026). IPIGuard uses a tool dependency graph (An et al., 2025), Conseca derives contextual policies (Tsai & Bagdasarian, 2025), and FORGE enforces formal policies over tool operations (Palumbo et al., 2026). These approaches share PACE ’s concern with action authorization and differ in the evidence used. Their rules range over names, arguments, and task descriptions; 

PACE derives a separating cut from an execution graph and then demands a concrete hook binding for every cut edge. 20 Preprint MELON detects indirect injection by comparing the original action with a masked-prompt re-execution (Zhu et al., 2025), DataSentinel trains an adaptive detector through a minimax objective (Liu et al., 2025), and LlamaFirewall combines prompt, agent-alignment, and code guardrails (Chennabasappa et al., 2025). Structured-query and model-level defenses separate instructions from data or train the model to respect the distinction (Chen et al., 2025a;b). All of these compose with 

PACE , and our evaluation keeps a pre-filter’s AUROC, TPR, and FPR apart from end-to-end agent security. AgentArmor reconstructs runtime traces as program graphs and applies a type system to security metadata (Wang et al., 2025). More recent monitors operate at argument and execution granularity: PACT supports fine-grained provenance and scoped discharge certificates (Fan et al., 2026), Auth-Graph separates observed provenance from request-derived authorization (Wang et al., 2026a), and CXI binds executed effects to a canonical manifest and requires fresh authority after relevant edits or repairs (Santos-Grueiro, 2026). Thus fine-grained authorization and re-authorization alone do not distinguish PACE . Its analysis couples a candidate graph cut to the intervention actually installed: separation survives exactly when that intervention blocks the terminal or severs every reachable argument edge, alongside authorization of the final call (Sections D.3 and 4.4). The evaluated restoration and repair paths make this distinction observable in the component study. IsolateGPT establishes isolation between LLM applications and the host (Wu et al., 2025), a separate boundary from these call-level checks. B.3 FORMAL FOUNDATIONS 

Complete mediation requires every security-relevant access to pass through a tamper-resistant, analyzable mechanism (Saltzer & Schroeder, 1975; Anderson, 1972), and runtime policy enforcement characterizes which trace properties execution monitors can enforce (Schneider, 2000). PACE is an edit automaton rather than a truncation automaton, since its actions rewrite and suppress arguments as well as halting the call, and that class is strictly more expressive (Ligatti et al., 2005; Hamlen et al., 2006). Lattice-based confidentiality (Denning, 1976) and language-level information-flow control (Myers, 1999; Sabelfeld & Myers, 2003) give the basis for source and sink labels, and TaintDroid and libdft show that labels do propagate through instrumented execution (Enck et al., 2010; Kemerlis et al., 2012). Our opaque-boundary ablation is built to respect that capability, not to deny it. Proof-carrying code attaches machine-checkable evidence that code satisfies a policy (Necula, 1997), and model-carrying code checks a model of an untrusted program against a safety property (Sekar et al., 2003). Both apply when the code slice is the whole security-relevant semantics and the model’s choice of that slice’s inputs is itself secret-independent, which is the positive case of Proposition D.1. 

PACE ’s runtime guarantee is deliberately weaker and more operational. The max-flow/min-cut theorem gives exact minimum-capacity separation for a fixed capacitated graph (L. R. Ford & Fulkerson, 1956), and our solver applies it directly; the registry costs are deterministic inputs, not calibrated probabilities.

Parallel edge instances stay distinct in the multigraph. Besides the nodes of Definition 1 the fold also records the agent’s stated intentions and plans, and the control and intent edges among them stay in 21 Preprint the audit record and never reach a cut. Values and effects connect through an operation node, so the construction has no direct Data -to-Data and no Data -to-Terminal edge; Section D.4 uses both facts. The host maintains a provenance map ν for live values and applies five rules, which are the complete set of flow-edge emitters. (E1) Before certification, each schema-defined proposal argument emits an edge from its data or resource node to the fresh operation node. (E2) A valid outcome receipt emits an edge from the operation to every schema-defined returned value, minting a fresh provenance identifier unless the adapter certifies the value as an unchanged pass-through. (E3) Such a pass-through keeps its identifier at the next declared position. (E4) Every proposal creates a fresh terminal T (qt) and emits op( qt) → T (qt) before dispatch, and the versioned unsafe-effect rule labels that terminal. (E5) A confirmed outcome of a schema-declared write mints a new resource version node Rv+1 , commits 

op( q) → Rv+1 , and gives Rv+1 the union of the origin and protection labels of that call’s committed inputs. Rules E2 and E5 fire at finalization, so their edges are committed and not proposed. These rules emit structure, not a claim about the semantics of hidden computation. Instance status follows from the log: a refusal expires the current proposal edges, OUTCOME commits them together with the authenticated output edges, UNKNOWN commits the proposal alone, and 

BLOCKED or CANCEL commits no flow. The frontier Bt is folded as in Section 4.2 from the origin-labeled live-value set, over committed flow edges only, so Bt ∩ Tbad = ∅ and no node enters Bt

through a current proposed edge; in particular the fresh operation and terminal of qt stay out. The disjointness Pt ∩ Ut = ∅ recorded in Section 4.2 follows for the same reason, since protection labels apply only to data and resource nodes. 

Lemma C.1 (Every unsafe path crosses a current edge) . Let Ep(qt) be the proposed flow-edge instances of at. Every directed path from Bt ∪ Pt to nonempty Ut contains an edge in Ep(qt). If the terminal in-edge admits block_call , that edge alone is a finite-capacity cut. Proof. Nonempty Ut contains only T (qt), which is fresh, disjoint from the source set, and by (E4) has the single proposed in-edge op( qt) → T (qt). Every path to it therefore ends with that current edge, and removing it separates the terminal. When it has a nonempty binding to block_call ,Equation (6) gives it a finite value. Declared costs are strictly positive rationals with a fixed denominator, which the implementation scales to integers. Positivity matters: with a zero-cost action a minimum-cost separating set could be padded arbitrarily, and the verifier’s set equality in Section C.4 would be ill posed. The infinity sentinel exceeds the sum of every finite capacity, and acceptance separately rejects a cut containing it. Nodes and edge instances carry a canonical order with the terminal edge first, which is what makes the selection in Proposition D.2 single-valued. Builder and verifier therefore agree without floating-point arithmetic and without depending on which minimum cut a flow solver happens to return. The untrusted frontier. Let St hold the untrusted-origin entries of the live-value set at σt. The verifier computes Bt by closing St over committed flow edges and dropping terminals, which loses nothing since a terminal has no out-edge. Proposed edges never advance the closure. If they did, one untrusted argument would collapse every call into terminal blocking, since the proposal itself would carry the frontier to the operation node it just created. 

Severance contracts. An action lies in Sev (e) when its warrants guarantee that, once installed, no execution of this call takes a real link whose represented segment contains e. The contract is about the call and not about the graph, so observation and user confirmation sever nothing: they change what the operator sees, not what the call can do. This is also why Sev is declared by the deployment while Impl is declared by the adapter. The adapter knows which hooks exist; only the deployment can assert that installing one removes a real dependency. 

The two redaction warrants. Redaction on a data edge lies in Sev (e) only under two declarations. The adapter warrants that the emitted value is independent of the original in content, length, and structure, so a length-preserving mask does not qualify. The registry warrants, per operation and argument position, that the call’s occurrence does not depend on that argument. Its default is that occurrence may depend, since no adapter knows whether the model would have proposed this call with a different argument. Miss either warrant and the argument edge has no severing action. Persistence of previously installed entries carries nothing, since after the committed state changes an old cut may be bypassed by a new edge. Execution is prevented by token discipline instead, which makes this a reference-monitor invariant and not a further confinement argument. H2 is a completeness assumption on the deployment’s effect registry, and without it the statement says only that nothing leaks through boundaries the deployment labelled correctly. The corollary is stated for PACE -C because PACE -P has executing branches without a grounded path certificate. Under the semantically sound labels of Section C.6, an outward or irreversible effect cannot satisfy R2’s three conjuncts. Outside R2, an unrepaired dispatch, including R3 and a restored P block, requires all nine effect obligations to pass; otherwise the only executing route is a registry-declared repair of a repairable verdict. This proves the payload-independent claim in Section 4.2: an out-of-authority outward or irreversible effect can execute only through such a repair, given sound request compilation, schema coverage and semantics, validators and declassifiers, complete mediation of the effects, and application of every required hook. Because repairs are not rechecked by R6, the argument does not certify their final effects. R2 and restoration likewise do not establish the episode confinement invariant. A leaking R2 call would require an unsound label or a missing sink/persistence declaration; reversibility alone is not its admission test. The per-call theorem applies to PACE -P only when its actual installed action satisfies all the theorem’s premises.

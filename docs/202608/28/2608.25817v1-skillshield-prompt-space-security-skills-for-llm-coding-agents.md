## 摘要
编程智能体以其开发者的权限编辑文件并执行 shell 命令，这使得恶意请求能够直接转化为有害行为或功能性恶意软件。现有的防御措施具有互补的局限性：仅使用 API 的部署者无法进行权重级对齐，而输入过滤器和执行边界监控器则需要在智能体的运行轨迹中添加辅助分类或检查组件。因此，我们推出了 SkillShield，这是一种系统提示词防御方案，它能从已知攻击或记录的智能体失败案例中离线合成安全技能。这些技能在会话开始时被注入到系统提示词中，并在整个工具使用循环中保持激活状态。与引用监视器不同，它们通过定义模型在执行期间应遵循的安全策略来保护系统。由于系统提示词空间有限，我们研究了三种固定预算的配置范围：全类别（all-classes），即用一种技能覆盖所有威胁类别；按捆绑（per-bundle），即用一种技能针对相关的子集；以及按类别（per-class），即用一种技能专门针对单个已知类别并作为上限参考。这些方案都不需要运行时的请求分类或路由。在 RedCode 基准测试中，针对六种大语言模型，默认的全类别技能将恶意软件生成的严重程度从 3.37 降低到 0.58，并实现了 43.6% 的执行攻击成功率，这与 Llama Guard 3 的 42.7% 相当，且无需其独立的 8B 分类器。按捆绑和固定类别的设置进一步将该比率分别降低到 36.2% 和 14.5%。在两种非自适应越狱家族的测试下，SkillShield 在防止恶意软件生成方面继续优于所有基准模型。在 731 个良性任务描述中，SkillShield 的平均安全拒绝率为 0.14%。这些结果证明了提示空间安全技能在防止 LLM 编程智能体产生有害行为和生成恶意软件方面的潜力。

## Abstract
A coding agent edits files and executes shell commands with its developer's privileges, allowing malicious requests to translate directly into harmful actions or functional malware. Existing defenses have complementary limitations: weight-level alignment is unavailable to API-only deployers, whereas input filters and execution-boundary monitors require auxiliary classification or checking components along the agent's trajectory. We therefore introduce SkillShield, a system-prompt defense that synthesizes security skills offline from known attacks or recorded agent failures. These skills are injected into the system prompt at session start and remain active throughout the tool-use loop. Unlike a reference monitor, they protect the system by defining the security policies the model should follow during execution. Due to the limited system-prompt space, we examine three fixed-budget provisioning scopes: all-classes, with one skill covering all threat classes, per-bundle, with one skill targeting a related subset, and per-class, with one skill dedicated to a single known class and used as the upper-bound reference. None requires runtime request classification or routing. Across six large language models on RedCode, the default all-classes skill reduces malware-generation severity from 3.37 to 0.58 and achieves a 43.6% execution attack success rate, comparable to Llama Guard 3's 42.7% without its separate 8B classifier. The per-bundle and class-fixed per-class settings further reduce this rate to 36.2% and 14.5%, respectively. Under two non-adaptive jailbreak families, SkillShield continues to outperform all baselines on malware generation. Across 731 benign task descriptions, SkillShield yields a mean safety-refusal rate of 0.14%. These results demonstrate the potential of prompt-space security skills to prevent harmful actions and malware generation for LLM coding agents.

### 2. 论文提出的方法论
SkillShield 的核心思想是**离线合成安全技能（Security Skills）**，并在会话开始时将其完整注入到系统提示词中。

* **安全技能的结构**：每个技能是一个 Markdown 文档，包含固定的拒绝前言（Preamble，要求完全拒绝，不进行“安全改写”）、威胁概述、检测规则和拒绝指令。
* **两种技能合成策略（算法流程）**：
  1. **主动挖掘（Proactive Mining）**：利用已知攻击语料库，通过合成器 LLM 提取具体的技术特征（如危险命令模式、敏感路径前缀、库调用序列），形成可机械化检查的规则。
  2. **反应式学习（Reactive Learning）**：利用未防御智能体在攻击中失败的真实轨迹，进行事后剖析（Post-Mortem），提炼出攻击者隐藏在不同表象下的恶意意图（Intent），帮助智能体识别复杂的社会工程学或伪装手段。
* **三种部署范围（Provisioning Scopes）**：
  由于系统提示词空间有限（预算 $L$ 设为 10,000 字符），SkillShield 设计了三种配置：
  * **全类别（All-classes）**：用一个技能覆盖所有威胁类别（适用于通用场景）。
  * **按捆绑（Per-bundle）**：将相关威胁按机制（如文件系统、网络流出等）分组，一包一技能。
  * **按类别（Per-class）**：一类一技能，作为已知精确威胁时的性能上限参考。

### 6. 主要结论与发现
* **防御极其有效**：在默认的“全类别”配置下，SkillShield 将恶意软件生成的严重程度（AvgS）从 3.37 降至 0.58，执行攻击成功率（ASR）降至 43.6%（与需要独立 8B 分类器的 Llama Guard 3 的 42.7% 相当）。
* **细粒度配置更优**：如果预先知道威胁范围，“按捆绑”和“按类别”配置可将执行 ASR 分别进一步降低至 36.2% 和 14.5%。
* **极低的良性误报**：在 731 个良性软件工程任务中，SkillShield 的平均安全过度拒绝率仅为 **0.14%**（36 个配置中有 32 个低于 0.68%）。
* **合成流失与拼接优势**：实验发现，在固定提示词预算下，直接将各分类的优秀技能进行**物理拼接并截断**，其效果（ASR 26.5%）显著优于通过 LLM 迭代合成的捆绑技能（ASR 36.2%），表明当前的 LLM 合成流程在融合多类别规则时会丢失关键技术细节。

### 7. 优点
* **部署零门槛、零运行时开销**：无需修改模型权重，不依赖额外的运行时分类器或监控组件，非常适合仅能调用 API 的开发者。
* **多步骤持续保护**：由于安全策略常驻于系统提示词中，它能在智能体与环境交互的整个生命周期（多步 Tool-use 循环）中持续生效，防止中间步骤引入的间接注入。
* **双轨合成机制**：结合了主动挖掘（规则具体、易审计）和反应式学习（关注意图、泛化性强）的优势。
* **极高的实用价值**：在保持高安全性的同时，几乎不影响智能体处理良性开发任务的正常响应（误报率极低）。

---

### 8. 不足与局限
* **提示词容量限制（Pigeonhole 原理）**：由于系统提示词长度有限，当需要覆盖的威胁类别极多时，技能的细节丰富度会下降，导致防御效果在宽泛场景下有所衰减。
* **对弱指令遵循模型的依赖性**：防御效果高度依赖于基座模型遵循系统提示词的能力。在一些较弱的模型（如 Nemotron-Nano）上，防御效果的提升不如在强模型（如 DeepSeek V3.2）上明显。
* **自适应越狱风险**：虽然在非自适应越狱（如 ArtPrompt）下表现良好，但如果攻击者能够直接获取系统提示词并针对 SkillShield 的具体规则进行白盒对抗优化，该防御可能会被绕过。
* **未评估良性任务的最终完成率**：实验仅评估了良性任务的“安全过度拒绝率（FPR）”，未评估注入安全提示词后是否会因上下文变长而间接降低智能体解决复杂软件工程任务的成功率（Benign Task Completion Rate）。

## 摘要
安全评估对于评估已对齐的大语言模型（LLM）在面对越狱攻击时是否保持鲁棒性至关重要。然而，现有的自动化测试方法在很大程度上依赖于响应层面的反馈：每个候选提示词通常需要生成目标模型的响应以评估其攻击有效性。这一过程不仅成本高昂，更重要的是，在强对齐模型上仅能提供稀疏的指导，因为大多数候选提示词都会因相同的失败结果而被拒绝。本文提出了 NeuronFuzz，这是一个白盒模糊测试框架，它利用内部安全神经元作为连续执行反馈来进行 LLM 安全评估。SafetyOracle 将安全神经元的激活转化为连续的安全警报分数，作为模糊测试的反馈，该分数可以在预填充（prefill）阶段获取，从而在模糊测试循环中消除了响应生成过程。为了构建 SafetyOracle，NeuronFuzz 使用模板无关的有害和良性输入以及稳定性感知选择，来识别一组紧凑的安全神经元，其激活能够捕捉有害意图识别。此外，由于安全警报分数是可微的，NeuronFuzz 利用其梯度来识别安全敏感的模板位置，并使用掩码语言模型生成流畅且上下文兼容的变异，同时保留原始有害负载并避免引入额外的优化变量。我们在 21 个文本和多模态模型上对 NeuronFuzz 进行了评估。在五个白盒源模型中，它实现了 76-100% 的越狱发现率，比基准方法高出多达 48 个百分点。其优化的模板还可以零样本迁移到开源权重模型和六个闭源目标模型，平均攻击成功率（ASR）和前 5 名集成 ASR（EASR）分别达到 69.6%/92.6% 和 44.1%/60.0%。

## Abstract
Safety evaluation is critical for assessing whether aligned Large Language Models (LLMs) remain robust against jailbreak attacks. Existing automated testing methods, however, largely rely on response-level feedback: each candidate prompt typically requires generating a target-model response to evaluate its attack effectiveness. This process is expensive and, more importantly, provides only sparse guidance on strongly aligned models, where most candidates are rejected with the same failure outcome.   This paper presents NeuronFuzz, a white-box fuzzing framework that exploits internal safety neurons as continuous execution feedback for LLM safety evaluation. A SafetyOracle converts safety-neuron activations into a continuous safety alarm score that serves as feedback for fuzzing and can be obtained during prefill, eliminating response generation from the fuzzing loop. To construct the SafetyOracle, NeuronFuzz uses template-invariant harmful and benign inputs and stability-aware selection to identify a compact set of safety neurons whose activations capture harmful-intent recognition. Moreover, since the safety alarm score is differentiable, NeuronFuzz uses its gradients to identify safety-sensitive template positions and a masked language model to generate fluent, context-compatible mutations while preserving original harmful payload and avoiding additional optimization variables. We evaluate NeuronFuzz across 21 text and multimodal models. Across five white-box source models, it achieves a 76-100% jailbreak discovery rate, outperforming baselines by up to 48 percentage points. Its optimized templates further transfer zero-shot to open-weight and six proprietary target models, achieving average ASR and top-5 ensemble ASR (EASR) of 69.6%/92.6% and 44.1%/60.0%, respectively.

### 1. 核心问题与整体含义
*   **研究动机**：现有的自动化大语言模型（LLM）安全评估方法（如红队测试、模糊测试）主要依赖“响应级反馈”。这意味着必须等待模型生成完整回复，再由外部评判器（如另一个 LLM）判断是否越狱成功。
*   **核心痛点**：
    1.  **反馈稀疏**：对于强对齐模型，大多数攻击尝试都会被拒绝，产生相同的失败结果，导致优化算法无法区分哪些尝试“更接近成功”。
    2.  **成本高昂**：自回归生成 Token 的过程极其耗时且计算昂贵。
*   **研究目标**：提出一种利用模型内部信号（白盒信息）的模糊测试框架，在不生成响应的情况下提供连续、高密度的反馈。

### 2. 方法论
*   **核心思想**：利用 LLM 内部的“安全神经元”激活状态作为连续的执行反馈信号，构建一个名为 **SafetyOracle** 的轻量级分类器。
*   **关键技术细节**：
    1.  **SafetyOracle 构建**：
        *   **模板无关提取**：通过成对的有害/良性输入（共享相同的越狱模板）来提取 MLP 层的激活值，确保信号捕捉的是“有害意图”而非“模板风格”。
        *   **稳定性感知选择**：利用 Bootstrap 稳定性选择算法，从数万个神经元中筛选出对有害意图反应最稳定、最紧凑的神经元子集。
        *   **连续评分**：使用 Elastic Net 逻辑回归将神经元激活转化为 0 到 1 之间的“安全警报分数”（$S_{alarm}$）。
    2.  **梯度引导变异**：
        *   由于 $S_{alarm}$ 是可微的，通过反向传播计算输入 Token 的梯度，精确定位对安全信号影响最大的模板位置。
    3.  **上下文兼容变异**：
        *   使用掩码语言模型（MLM，如 ModernBERT）在梯度选定的位置生成语义连贯的替代 Token，既破坏了防御，又保持了自然语言的流畅性。
*   **流程**：种子调度 -> 梯度定位敏感位置 -> MLM 变异 -> 目标模型预填充（Prefill）获取激活 -> SafetyOracle 评分 -> 更新调度器。

### 6. 主要结论与发现
1.  **高效性**：NeuronFuzz 在白盒模型上达到了 **76-100% 的越狱发现率**，且每次发现所需的响应生成数（RGD）固定为 1.0（仅用于最终验证）。
2.  **强迁移性**：在白盒源模型上优化的模板可以“零样本”迁移到闭源 API。在 Gemini-2.5-Pro 上达到了 85.2% 的 ASR。
3.  **跨模态通用性**：文本阶段优化的模板能有效提升视觉语言模型（VLM）在有害图像识别上的越狱成功率。
4.  **防御价值**：SafetyOracle 可以作为一种极其轻量且准确的输入侧检测器（AUROC > 0.95），在模型开始生成回复前就拦截攻击。

### 7. 优点
*   **创新视角**：将模糊测试的“覆盖率引导”思想转化为“安全神经元激活引导”，解决了 LLM 安全测试中反馈稀疏的根本问题。
*   **性能卓越**：在保证高攻击成功率的同时，大幅降低了计算开销（无需自回归解码）。
*   **鲁棒性强**：生成的变异提示词比 GCG 等方法更符合自然语言分布，能绕过困惑度（Perplexity）过滤器。

### 8. 不足与局限
*   **白盒依赖**：构建 SafetyOracle 和计算梯度需要访问模型的中间层激活和参数，这限制了其在完全无法获取权重的闭源模型上的直接优化能力（虽然迁移性弥补了这一点）。
*   **神经元漂移**：如果目标模型进行了微调或版本更新，原本识别的安全神经元可能会失效，需要重新进行一次性的 Oracle 训练。
*   **多轮对话限制**：目前主要集中在单轮提示词越狱，对于复杂的多轮对话诱导攻击探讨较少。

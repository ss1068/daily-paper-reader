## 摘要
大语言模型（LLM）智能体越来越多地在不受信任的网页、文档、工具和持久化状态上运行，同时对安全敏感资源行使权限。现有的防御措施通常只保护规划过程或单个工具的交互，但持久化智能体面临着更广泛的威胁：攻击者控制的数据可以改变控制流、进入安全敏感的工具参数，或破坏后续的查询。我们提出了 SPA，这是一种计划优先的架构，旨在保护规划、执行和跨查询的状态重用。SPA 在每次查询时调用一次规划器，以声明式领域特定语言生成完整的可执行计划，然后应用双格（dual-lattice）信息流控制，在显式数据流和控制依赖中跟踪机密性和完整性。为了在不向规划器重新暴露不受信任负载的情况下支持持久化，SPA 将执行结果存储为带标签的工件，并在后续规划中仅公开语义元数据。我们在 AgentDojo 和 AgentDojo-MQ 上评估了 SPA，后者是我们用于衡量安全状态重用和延迟攻击的多查询扩展。在“tool_knowledge”攻击下，带有信息流控制的 SPA 将 AgentDojo 上的攻击成功率降至零，在 AgentDojo-MQ 上降至 0.2%。我们的结果表明，计划优先的执行结合保留标签的持久化可以显著增强持久化 LLM 智能体，同时也揭示了严格的完整性强制执行所带来的安全与效用之间的重要权衡。

## Abstract
Large language model (LLM) agents increasingly operate over untrusted webpages, documents, tools, and persistent states while exercising authority over security-sensitive resources. Existing defenses typically protect either planning or individual tool interactions, but persistent agents face a broader threat: attacker-controlled data can alter control flow, enter security-sensitive tool arguments, or compromise later queries. We present SPA, a plan-first architecture that secures planning, execution, and cross-query state reuse. SPA invokes the planner once per query to generate a complete executable plan in a declarative domain-specific language, then applies dual-lattice information-flow control to track confidentiality and integrity across explicit data flows and control dependencies. To support persistence without re-exposing untrusted payloads to the planner, SPA stores execution results as labeled artifacts and reveals only semantic metadata during later planning. We evaluate SPA on AgentDojo and AgentDojo-MQ, which is our multi-query extension for measuring secure state reuse and delayed attacks. Under the 'tool_knowledge' attack, SPA with information-flow control reduces attack success to zero on AgentDojo and 0.2% on AgentDojo-MQ. Our results show that plan-first execution combined with label-preserving persistence can substantially strengthen persistent LLM agents, while revealing an important security-utility tradeoff introduced by strict integrity enforcement.

*   **核心问题**：持久化大语言模型（LLM）智能体在跨多轮查询运行过程中，面临严重的**间接提示注入（Indirect Prompt Injection）**威胁。攻击者控制的外部数据（如网页、邮件、工具输出）不仅能篡改当前的控制流，还能作为参数进入安全敏感工具，甚至潜伏在持久化存储中，在未来的查询中被激活（延迟攻击）。
*   **研究背景**：现有的防御机制（如交替式防御或简单的计划优先防御）要么无法完全隔离不可信输出对规划器的影响，要么无法处理跨查询的状态重用安全。
*   **整体含义**：本文提出了 **SPA** 架构，旨在通过“计划优先”和“信息流控制（IFC）”相结合的方式，确保智能体在规划、执行及跨查询状态重用全生命周期内的安全性。

### 2. 方法论：核心思想与关键技术
SPA 的核心思想是将**规划（Planning）与执行（Execution）彻底分离**，并对数据流向进行严格的数学化约束。
*   **计划优先架构（Plan-First Architecture）**：
    *   规划器在每次查询时仅调用一次，生成一种声明式的**领域特定语言（DSL）**计划。
    *   规划器**永远无法看到**工具输出的原始负载（Payload）或持久化存储中的具体数值，只能看到语义元数据。
*   **声明式 DSL**：包含 6 种基本操作：`retrieve`（检索工件）、`tool`（调用工具）、`q-llm`（隔离环境下的 LLM 处理）、`display`（展示结果）、`condition`（分支）和 `loop`（循环）。
*   **双格信息流控制（Dual-Lattice IFC）**：
    *   **机密性（Confidentiality）**：遵循 Bell-LaPadula 模型，防止敏感信息流向低权限终端。
    *   **完整性（Integrity）**：遵循 Biba 模型，防止低完整性（不可信）数据驱动高完整性（安全敏感）的操作。
    *   系统在执行前静态验证计划中的所有数据依赖和控制依赖是否符合安全策略。
*   **保留标签的持久化（Label-Preserving Persistence）**：
    *   执行结果被存储为“工件（Artifacts）”，每个工件关联一个安全标签（C, I）。
    *   后续查询重用工件时，标签会被恢复并重新参与 IFC 验证，确保“污染”能跨查询追踪。
*   **抽象规划模式（Abstract Planning）**：可选模式，通过合成抽象工具模式来隐藏真实工具的元数据，防止工具元数据层面的注入攻击。

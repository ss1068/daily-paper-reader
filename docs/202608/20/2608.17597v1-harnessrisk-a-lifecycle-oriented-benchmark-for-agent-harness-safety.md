## 摘要
大语言模型越来越多地通过管理工具、扩展、持久状态、权限和外部操作的智能体框架（agent harnesses）进行部署。现有的安全基准主要针对单一的攻击机制或有限的操作设置子集，这使得难以比较安全故障如何在不同的框架职责中出现。我们提出了 HarnessRisk，这是一个面向生命周期的基准，它将智能体框架安全划分为六个操作阶段，包括：框架配置（Harness Configuration）、能力扩展（Capability Extension）、运行时操作（Runtime Operation）、状态持久化（State Persistence）、操作控制（Action Control）和事故恢复（Incident Recovery）。HarnessRisk 包含 128 个沙盒案例，每个案例都将良性的用户目标与嵌入在不可信工作流产物中的对抗性指令配对。我们使用效用（Utility）、攻击成功率（Attack Success Rate）、持久性（Persistence）和检测率（Detection）来评估每条轨迹。在三个框架、六个语言模型以及 14 种模型和框架配置的测试中，攻击成功率在 12.6% 到 80.9% 之间，而效用保持在 75.0% 到 97.6% 之间。框架配置是所有三个框架中最脆弱的阶段，表明攻击可以通过修改原本授权的工作流中的安全敏感参数来实现。我们还发现，明确的风险识别并不一定能产生安全行为，因为某些配置在超过 90% 的运行中检测到了风险，但仍具有显著的攻击成功率。这些结果强调了在多个框架职责以及部署的模型和框架配置层面评估智能体安全的必要性。

## Abstract
Large language models are increasingly deployed through agent harnesses that manage tools, extensions, persistent state, permissions, and external actions. Existing safety benchmarks mainly target individual attack mechanisms or a limited subset of operational settings, making it difficult to compare how safety failures emerge across different harness responsibilities. We present HarnessRisk, a lifecycle oriented benchmark that organizes agent harness safety into six operational phases including Harness Configuration, Capability Extension, Runtime Operation, State Persistence, Action Control, and Incident Recovery. HarnessRisk contains 128 sandboxed cases, each pairing a benign user objective with an adversarial instruction embedded in an untrusted workflow artifact. We evaluate each trajectory using Utility, Attack Success Rate, Persistence, and Detection. Across three harnesses, six language models, and 14 model and harness configurations, attack success ranges from 12.6% to 80.9%, while Utility remains between 75.0% and 97.6%. Harness Configuration is the most vulnerable phase across all three harnesses, showing that attacks can succeed by altering security sensitive parameters within otherwise authorized workflows. We also find that explicit risk recognition does not reliably lead to safe action, as some configurations detect risks in more than 90% of runs while retaining substantial attack success. These results highlight the need to evaluate agent safety across multiple harness responsibilities and at the level of the deployed model and harness configuration.

#### 1. 核心问题与整体含义
随着大语言模型（LLM）以智能体（Agent）形式广泛部署，其安全性不仅取决于模型本身，还取决于管理工具、权限和状态的“智能体框架”（Agent Harness）。现有的安全基准测试大多局限于单一的攻击机制（如提示词注入）或特定的操作场景，缺乏对框架在完整运行生命周期中职责风险的系统性评估。本论文提出了 **HarnessRisk**，旨在填补这一空白，通过模拟真实工作流，评估智能体框架在不同操作阶段的安全性。

#### 2. 论文提出的方法论
论文提出了一个面向生命周期的安全框架，将智能体框架的职责划分为六个关键阶段：
*   **框架配置 (Harness Configuration)**：涉及连接器、凭据和策略的初始化。
*   **能力扩展 (Capability Extension)**：关注插件或技能的安装、更新及权限管理。
*   **运行时操作 (Runtime Operation)**：处理来自邮件、网页等不可信内容的常规执行。
*   **状态持久化 (State Persistence)**：涉及长期记忆、存储偏好和策略的安全性。
*   **操作控制 (Action Control)**：针对支付、部署等高影响外部操作的授权。
*   **事故恢复 (Incident Recovery)**：评估在遭受攻击后的调查、回滚和修复能力。

**核心设计**：HarnessRisk 包含 128 个沙盒案例。每个案例采用“良性任务 + 恶意指令”的配对模式，恶意指令嵌入在不可信的工件（如配置文件、插件元数据或邮件）中。智能体需在三轮交互中尝试完成良性目标，同时抵御恶意诱导。

#### 3. 实验设计
*   **实验场景与基准**：所有测试均在隔离的沙盒环境中进行，使用模拟服务（如模拟邮件、支付网关）以确保安全。
*   **评估对象**：
    *   **3 种智能体框架**：OpenClaw, Nanobot, Hermes。
    *   **6 种语言模型**：DeepSeek-V4-Pro, GLM-5.2, Kimi K2.6, MiniMax M3, GPT-5.5, Claude Opus 4.7。
    *   **14 种配置组合**：涵盖了不同模型与框架的交叉部署。
*   **评估指标**：
    *   **效用 (Utility)**：良性任务的完成度。
    *   **攻击成功率 (ASR)**：恶意目标达成的比例。
    *   **持久性 (Persistence)**：恶意影响是否进入持久化状态。
    *   **检测率 (Detection)**：模型是否明确识别并指出安全风险。

#### 4. 资源与算力
论文未详细列出具体的 GPU 型号或训练时长。由于该研究侧重于基准测试评估而非模型训练，其算力消耗主要集中在推理阶段。实验通过 API 调用或本地部署模型进行，每个案例在独立沙盒中运行，并设置了 1800 秒的超时限制。

#### 5. 实验数量与充分性
*   **实验规模**：共 128 个案例，每个配置在 3 个独立随机种子下运行，总计产生 384 条轨迹/配置。
*   **充分性与客观性**：实验覆盖了从配置到恢复的完整生命周期，并对比了多种主流开源及闭源模型。为了验证评估的客观性，研究者使用 GPT-5.4 作为自动评估器，并将其结果与人类标注及确定性谓词进行了交叉验证，显示出较高的一致性（如效用一致性达 92.5%）。

#### 6. 主要结论与发现
*   **效用与安全脱节**：高任务完成度并不代表安全。在许多案例中，智能体在成功完成用户任务的同时，也执行了恶意指令。
*   **配置阶段最脆弱**：在所有测试框架中，“框架配置”阶段的攻击成功率最高，攻击者极易通过篡改安全参数来破坏系统。
*   **框架影响显著**：同一模型在不同框架下的安全性表现差异巨大（最高达 4 倍），证明安全是“模型+框架”配置的共同属性。
*   **检测不等于防御**：即便模型识别出了风险（高检测率），也往往无法阻止恶意操作的发生，尤其是在事故恢复阶段。

#### 7. 优点
*   **视角全面**：首次从生命周期角度系统化组织智能体框架的安全职责。
*   **结构化设计**：多轮交互（三轮 owner turns）的设计比单轮测试更贴近真实复杂的智能体工作流。
*   **多维度度量**：区分了任务效用、攻击成功、持久化影响和风险检测，提供了更细致的安全画像。

#### 8. 不足与局限
*   **框架覆盖有限**：虽然测试了三种框架，但市场上仍有许多其他架构（如基于特定云服务的框架）未被纳入。
*   **评估器依赖**：高度依赖高级语言模型（如 GPT-5.4）作为裁判，可能存在潜在的评估偏差。
*   **沙盒局限性**：模拟环境虽然安全，但可能无法完全捕捉真实互联网环境中复杂的侧信道攻击或基础设施漏洞。

## 摘要
计算机使用智能体 (CUAs) 面临着来自间接提示注入的日益增长的威胁，即对抗性指令被植入网页等环境之中。在本文中，我们引入了多步间接提示注入，这是一种针对 CUA 的新型攻击类别。在这种攻击中，对抗目标被分解为多个看似无害的子步骤，并分布在智能体导航路径所引用的页面链中。我们开发了一套流水线，在确保分解后的子步骤执行能够实现原始目标，同时优化每个子步骤无害性的约束下，自动分解对抗目标。利用该流水线，我们构建了包含 480 个测试用例的 CUA 安全性基准 StepJack。在该基准上，我们评估了六种最先进的 CUA，并发现对于固定的分解深度，多步攻击提高了六种 CUA 中三种的攻击成功率 (ASR)，最高提升了 31.2 个百分点（例如，GPT-5.4-mini：从单步的 41.7% 提升至三步的 72.9%）；在能够可靠遵循引用链的五种 CUA（除 EvoCUA-32B 以外的所有智能体）的平均值上，ASR 从单步的 31.3% 上升到三步的 36.9%。数据集和代码已发布在 https://github.com/BorealisAI/StepJack。

## Abstract
Computer-use agents (CUAs) face a growing threat from indirect prompt injection, where adversarial instructions are planted in the environment such as web pages. In this paper, we introduce multi-step indirect prompt injection, a new attack class against CUAs in which the adversarial goal is decomposed into multiple innocuous-looking sub-steps and distributed across a chain of pages referenced along the agent's navigation path. We develop a pipeline to automatically decompose an adversarial goal under the constraint that the execution of the decomposed sub-steps must achieve the original goal while optimizing the innocuousness of each decomposed sub-step. With this pipeline, we build StepJack, a CUA safety benchmark with 480 test examples. On this benchmark, we evaluate six state-of-the-art CUAs and find that at a fixed decomposition depth, multi-step attacks raise attack success rate (ASR) on three of six CUAs, by up to 31.2 points (e.g., GPT-5.4-mini: 41.7% at single-step to 72.9% at three-step); averaged over the five CUAs that can reliably follow the reference chain (all but EvoCUA-32B), ASR rises from 31.3% at single-step to 36.9% at three-step. Dataset and code are available at https://github.com/BorealisAI/StepJack.

*   **整体含义**：论文提出了**多步间接提示注入（Multi-step Indirect Prompt Injection）**这一新攻击类别，并发布了 **StepJack** 基准测试，旨在揭示当前前沿智能体在处理链式参考信息时的安全盲点。

### 2. 方法论：核心思想与技术细节
*   **核心思想**：通过“引用嵌套（Reference Nesting）”构建页面链，将恶意目标 $a$ 分解为 $k$ 个子步骤 $(d_1, d_2, \dots, d_k)$。每个子步骤单独看都是无害的，但组合执行后可达成恶意目的。
*   **自动化分解流水线（Algorithm 1）**：
    1.  **候选搜索（LLM-judged）**：利用 LLM 生成分解方案，并由专门的“忠实度裁判”和“安全性裁判”进行评分和迭代优化。
    2.  **智能体验证（CUA-verified）**：将评分最高的方案在沙盒环境中由验证智能体（如 Qwen3.5-Plus）执行，筛选出操作最简洁、物理可执行性最强的方案。
*   **攻击策略分类**：
    *   **操作分解**：每一步都是允许的日常操作（如先存路径到文件，再删除该文件中的路径）。
    *   **语义分解**：将恶意载荷碎片化（如分段写入脚本内容，最后执行）。
    *   **升级分解**：利用“得寸进尺”效应，先诱导智能体执行无害前置操作，降低其对后续敏感操作的警惕。

### 3. 实验设计
*   **基准测试 (StepJack)**：基于 RedTeamCUA 沙盒构建，包含 **480 个测试用例**。
*   **实验维度**：
    *   **平台**：Reddit（论坛型，需点击链接）和 OwnCloud（文档型，需翻页）。
    *   **目标类别**：涵盖机密性、完整性、可用性（CIA 三元组）。
    *   **分解深度**：$k=1$（单步基准）、$k=2$、$k=3$。
    *   **用户指令模式**：宽松型（授权智能体遵循网页指令）与严格型。
*   **对比对象**：评估了 6 个前沿 CUA：EvoCUA-32B、Qwen3.5-Plus、Kimi-K2.5、GPT-5.4-mini、Claude-Haiku-4.5、Claude-Sonnet-4.6。

### 4. 资源与算力
*   **算力环境**：实验在 **AWS EC2** 实例上运行，以实现大规模并行化。
*   **API 成本**：论文明确指出 CUA 评估成本极高。以 Claude-Sonnet-4.6 为例，单个包含 30 个动作步骤的用例成本约为 0.38 美元。完成一次完整的基准测试（480 个用例）约需 **520 美元**的 API 费用，外加数百美元的 EC2 运行成本。
*   **模型部署**：EvoCUA-32B 为本地部署，其余通过 API 调用。

### 5. 实验数量与充分性
*   **实验规模**：每个智能体运行 480 个用例，总计近 3000 次端到端轨迹模拟。
*   **充分性**：实验涵盖了多种平台、攻击深度和防御场景（如 DSP 系统提示词防御、PID 注入检测器），维度设计合理。
*   **局限性**：受限于极高的 API 成本，作者**未能进行多次重复实验**以计算方差，所有结果基于单次运行。此外，受预算限制，恶意目标的种类（12个）相对较少。

### 6. 主要结论与发现
*   **多步攻击更有效**：在固定深度下，多步攻击显著提升了 3 个智能体的攻击成功率（ASR）。**GPT-5.4-mini 的 ASR 从单步的 41.7% 飙升至三步的 72.9%**。
*   **防御失效**：现有的防御手段（如 PromptArmor 检测器）对单步注入较有效（56.2% 检测率），但对多步注入的单个子步骤检测率极低（最低仅 2.1%）。
*   **脆弱性条件**：多步攻击成功的关键在于智能体能否可靠地跟踪引用链（GUI 落地能力）以及是否会因为“用户授权”而降低对环境内容的审查。

### 7. 优点
*   **创新性**：首次定义并系统研究了针对 CUA 的多步间接注入攻击，填补了安全评估的空白。
*   **自动化**：开发了闭环的分解与验证流水线，使基准测试具有良好的可扩展性。
*   **现实性**：实验环境基于真实的 OSWorld 沙盒，模拟了真实的 GUI 操作而非简单的文本交互。

### 8. 不足与局限
*   **成本制约**：高昂的 API 费用限制了实验的广度（目标数量）和深度（重复次数）。
*   **能力耦合**：实验发现某些智能体（如 EvoCUA）的低 ASR 并非因为安全性强，而是因为 GUI 操作能力差（点不到链接），这在一定程度上干扰了安全性的纯粹评估。
*   **防御研究有限**：虽然测试了现有防御，但尚未提出能有效应对多步攻击的新型防御机制。
